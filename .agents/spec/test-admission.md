# ImageShow 测试准入

> 修改与运行测试的授权见 [AGENTS.md 任务与权限](../../AGENTS.md#任务与权限)；执行顺序见 [测试与验证](../process/validation.md)。

项目只有一个完整验收 `npm run verify:release`，各功能的验证都并入这一入口；其组成与命令选择见 [测试与验证](../process/validation.md#命令选择)。

- 新功能、重构和普通修复默认沿用现有测试。只在以下情况改动受跟踪测试：
  1. 行为按用户要求变化，使现有断言失效：在原用例中改为现行行为。
  2. 改动触及数据持久与完整性、鉴权与权限、安全边界、取消与资源释放、跨模块故障恢复，或随机 API、配置、部署等公开契约，且完整验收中没有用例会因其出错而失败：在所属领域的现有用例中补最少的断言。
  3. 修复的缺陷曾漏过完整验收：在最接近的现有用例中补能复现它的断言。
- 新建测试文件、统一入口装配、场景选择器、`support/` 工具或固定夹具，须先说明理由并取得用户明确同意。
- 测试对象是跨模块的可观察契约。以下内容不作为测试对象：内部函数、单个组件或 Hook 的单元行为，实现细节，文案、文档格式、样式声明、文件清单和源码写法，测试工具自身，以及“旧功能、路由、字段或文件不存在”这类事实（包括测试或源码关键词黑名单）。
- 测试规模保持稳定。补断言时清理被覆盖的重复断言、临时复现、阶段 smoke 和过期夹具；同一事实只由一个合适入口负责。
- 测试以输入、操作和可观察结果组织。非法输入、鉴权和权限拒绝、未知请求的通用处理、取消、错误恢复、缓存失效、数据完整性和资源释放都是有效契约；去留按测试目的逐条判断，`not`、404 等否定断言同样适用这一标准。
- 测试代码和夹具中的 UUID、会话标识和 token 一律使用明确合成、确定性的测试值或测试专用生成器，并保留所测协议的格式与身份差异；真实环境的值不得写入测试。
- `scripts/tests/` 只保存受 Git 跟踪、在其他机器检出并按公开说明安装依赖后即可运行的测试、门禁和可公开夹具，所需输入全部来自受跟踪文件。依赖真实数据、外部私有资源或个人环境的验收，以及临时测试、测量与运行产物，留在 Git 忽略的根目录 `tests/`（见 [AGENTS.md 文档规则](../../AGENTS.md#文档规则)）；`data/` 只保存应用及其依赖服务的运行数据。
- 功能删除本身不授权改动测试。
