# ImageShow 审查流程

> 审查角色、候选定义、豁免与结论复用见 [交付规范](../spec/delivery.md#审查与提交前要求)。按其中要求完成必要验证后进入本流程；单独要求的只读审查只读取并报告，据实标明缺少的验收。

## 准备与复审

1. 明确基点及拟提交文件，区分无关的已有改动。审查实际候选及其完整上下文，不让未提交的改动掩盖候选缺陷；有依赖时先明确纳入范围或解决依赖。
2. 主进程自审，覆盖代码质量、重复、边界条件、错误处理、缓存失效、权限、资源清理、依赖方向、配置与依赖同步及用户流程；检查不可达代码、补丁叠加和被加重的文件职责。核对已有验收证据，源码审查结论与运行验收结论分开表述。
3. 确认文档、完成记录与当前候选一致，按交付规范核对所需验证及已有结论的适用范围；版本提交或发布候选已按 [测试流程](validation.md)固定版本、文档和 TODO。
4. 按交付规范需要独立复审时，交由全新子代理完整复审；复审输入包含全部取舍记录（见 [AGENTS.md 文档规则](../../AGENTS.md#文档规则)），与其冲突的建议须说明原理由已失效的依据。发现问题按下表回退，直至复审无问题。
5. 主进程终审并核对交付规范；全部所需结论齐备且问题解决后，才进入提交或推送。

## 变更后的回退

| 变化 | 处理 |
| --- | --- |
| 仅增加非功能性改动 | 主进程按 [交付规范](../spec/delivery.md#审查与提交前要求)自查并终审 |
| 复审或终审发现其他问题 | 主进程修复；满足 [重新核查条件](../../AGENTS.md#核查与验证边界)时，先按 [开发流程](development.md)更新容器并等待用户重新核查；在既有测试授权内重跑受影响测试及当前候选所需完整门禁，再换全新子代理完整复审、主进程终审。仍有问题时重复本行 |
| 已通过复审或门禁后，候选发生其他改动 | 按交付规范重新验证，再由全新子代理完整复审、主进程终审 |
| 不提交的本地文件改动 | 主进程自查，原独立复审结论继续有效；若改变门禁依赖的验证输入，按 [测试流程](validation.md)重跑完整门禁 |
| 审查或验收发现事项未完成 | 恢复相应 TODO 及验收边界，完成后按实际改动归入上文对应情形 |
| 远端发布失败，候选及门禁输入未变化 | 保留已有本地结论，按 release.md 记录失败点和恢复条件 |
