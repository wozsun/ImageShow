# 架构不变量

修改服务端数据流、一致性、Worker、配置或部署时读取。只记录约束与设计原因；实现细节以源码为准。

## 真相源与数据所有权

- 只支持单应用实例：宿主锁、图片投影协调器、Ingestion worker、限流、注册表缓存都按单进程设计，不为多实例增加分布式协调。
- PostgreSQL 是正式图片、词表、账号、存储注册表与后台任务的唯一真相源。图片只有 PG 事务提交后才正式入库，Redis 回执、前端卡片或临时文件都不能替代这一事实。
- Redis 只保存派生或临时状态：图片投影、查询缓存、随机近期历史、会话、限流，以及 Ingestion 未完成任务和紧凑 completed 回执。Redis 丢失时这些允许消失，PG 中已提交图片不受影响。
- Ingestion canonical 在所属队列期限内是未完成任务的唯一运行时权威，可跨窗口 / 会话恢复；不以 PG 会话表或 `data/temp` 文件建立第二套恢复真相，也不从临时文件反建任务。
- 图片 ID 由 Server 生成 UUIDv7，排序以 `image_time` 为准；`created_at` 是首次正式入库时间，`created_by` 在首次提交时冻结，之后不随编辑、删除、恢复或迁移改写。
- 正式对象键只由 UUID 派生，独立于设备、亮度、主题、作者、标签等可编辑 metadata。三档各存独立文件，内容相同也分别保存。分类编辑只更新 metadata 与必要投影；只有接入、存储迁移、永久删除和显式维护能创建、复制或删除正式对象。读路径只访问已生成对象，不实时编码、不探测补建、不降级到其他档位。
- 本地上传、URL、JSONL、微博统一进入 Ingestion；原始文件、处理结果与缩略图暂存于 `data/temp`，提交时才写入所选后端。外部原图代理和随机 `proxy` 只代理响应，不创建图片记录；`original` 指另行登记的外部 HTTPS 原图，不是站内保存的上传原文件。

## Redis 图片投影

- 协调器同时只有一个活动校验 / 重建任务；状态机只有一个所有者，拆文件不得产生第二实例或第二恢复权威。
- PG `ready_image_revision`（单行）是投影权威修订号。凡改变 ready 图片投影、筛选成员或统计的事务都在 COMMIT 前推进它；Redis 的 applied revision 只在精确同步或全量重建完成完整性校验后发布，不一致即关闭读门。
- 提交后在写栅栏内按旧投影与新 PG 投影做精确同步，超过同步预算只安排一次完整重建。Redis 同步失败绝不回滚已提交事务，而是关门重建；不得把旧值（如旧 `storage_slug`）重新发布。恢复任务入库失败时由同一状态机保留意图并有界重试。
- 读门关闭时，公开只读路径经统一 FIFO 准入有界回源 PG，等待或执行超限明确返回 429 / 503；后台返回 `503 redis_unavailable`。首次 Redis 能力校验成功前，冷启动门拒绝全部业务。
- 派生结果（属性索引、组合、统计）缺失、过期、revision 不符或超出容量 / 工作量预算时，只让本次请求放弃派生结果并回源，不关闭核心读门、不触发核心重建；超限时整份放弃，绝不发布截断的集合。
- 派生结果的访问登记（续期与 LRU 次序）由每个进程对同一结果实例在间隔内只执行一次，因为登记脚本会校验整张登记表，逐次登记的耗时随登记条目数增长并经单队列串行。实例由 revision、数量与实例 token（统计结果为内容摘要）确定；登记失败、丢弃、重新登记或清空可丢弃缓存后立即忘记，下一次读取重新登记。过期最多提前一个间隔，LRU 与 `last_accessed` 的精度随之为该间隔；间隔远小于过期时间。
- 公开回源使用惰性 reader scope：首个真实 SQL 才借连接，同一读取阶段复用并按调用顺序执行，阶段结束统一释放。被多个访客共享的任务（词表、统计、注册表加载）持有自己的取消信号和数据库作用域，单个访客只取消自己的等待；不借用某个访客绑定的 reader。图片读取作用域先结束，再读存储注册表，避免持连接嵌套等待准入。公开回源准入不限制管理事务和 Worker。
- 检查页和概览的 Redis 占用由各自查询即时测量；meta 中的内存值只是最近一次完整重建的快照，不能冒充当前占用。

## 一致性与锁

- 改变图片对象位置的操作共用“全局存储维护锁（共享 / 独占）+ 单图锁”，锁内重读 PG；位置以旧值 CAS 提交，数据库确认后才由持久任务清理源对象。Ingestion commit、自动亮度读取、迁移和永久删除都取同一单图锁，因此串行收敛。
- 正式对象写入前必须先登记持久 `move.cleanup` guard；未解决的 cleanup 同时是对应物理键的删除租约，见[存储](storage.md#正式写入guard-与删除租约)。
- 结果未知（COMMIT 回包丢失、请求超时、响应丢失）时按真值重读收敛；不能根据页面报错推断回滚，也不把超时当作成功或失败。客户端不自动重放写请求。
- 已开始的 PG 提交不因 Redis 断线、停机或请求取消而撤销；取得锁后开始的不可逆工作必须完成结算。请求取消、Worker 执行取消和事务结算由各自所有者处理，不借用超时或前端状态推断完成。
- 取消信号沿调用链显式传递：HTTP 路由传请求 signal，Worker 与任务传执行 signal，启动 / 停机传生命周期 signal，链路入口参数必填；确无取消来源的后台工作显式传 `neverAbortedSignal`，不以可选参数保留“无 signal”的第二条路径。只有仍存在合法无信号调用方的基础设施（失败清理、启动校验、通用 driver 选项等）保持可选；尚未逐链核对的既有可选链路在改动时按本条收敛。
- 图片编辑采用 last-write-wins，不存逐图编辑版本，也不以 `ready_image_revision` 仲裁编辑冲突。

## 后台任务

- 通用 jobs 层只拥有领取、execution token、续租、重试、公平调度、停机排空与历史裁剪；handler、payload 与结果语义归各领域。不同类型分别取得有界时间片，慢任务不阻塞其他类型。
- 每次领取生成新的 `execution_token`；续租和所有终态写入必须同时匹配 id、`running` 与 token，退出 `running` 的路径清空 token，租约超时后被重新领取的旧执行者不能写入迟到终态。退避与到期判断统一使用 PG 时钟；僵尸恢复与普通失败共用同一重试预算。
- 历史裁剪在锁定候选时跳过正在更新的行，避免删除并发重新入队的新意图；仍承担删除租约或删除意图的任务不裁剪（见[数据库](database.md#回收站与永久删除)）。
- Ingestion 使用独立的单实例 Redis worker，会话不进入通用任务表；Redis 恢复后先恢复 canonical 再领取新工作。

## 进程生命周期

- 启动：宿主锁 → 部署与运行配置 → 运行目录（含临时目录与 `data/asset`） → 空库初始化或非空库 readiness → 管理员与必要投影 → HTTP 与 Redis 监测；Redis 通过能力校验后才开放业务门并启动协调器和 Worker。
- `http-app` 与 CLI（密码恢复、healthcheck）的模块导入不得启动服务或产生初始化副作用。
- 停机：先停止接收请求和领取任务，HTTP、Worker、存储 driver 共用同一截止时间收尾，再在总上限内关闭 Redis、宿主租约与 PG；重复信号复用同一次收口。超时或失败记录未完成阶段并以失败状态退出，不提前释放仍有活动工作的宿主租约，不把中断当正常排空；重启后由各领域恢复。

## 运行配置

- `data/config.json` 由唯一进程内 store 持有：表单保存、磁盘重载和日志等级修改共用 FIFO 写租约，原子写入成功后才发布内存快照并通知 listener；listener 异常逐个隔离记录，不反转已持久化结果。
- 启动与磁盘重载按当前默认结构归一化：补齐缺失字段，递归删除未知、错误命名或废弃字段，保留合法值，校验后在变化时原子写回完整文件。表单保存严格校验完整结构，并携带快照 revision，基准过期返回 409。
- 正式文件替换后目录同步失败属于“持久化未确认”：回读判断磁盘是否为候选内容，内存保持旧配置并暂停后续写入，直到显式重载重新校验并持久化；不吞错报成功，也不盲目覆盖回滚。
- 存储后端与凭据保存在 PG，不进入 `config.json`。RuntimeConfig 的叶子到首次 seed 环境变量只有一个映射来源。
- 配置投影、默认补齐、未知字段清理、当前值校验、原子写回，以及数据库最小 readiness 与额外对象容忍属于长期契约。旧版本兼容只针对具体旧版本、字段、协议、路由、key 或代际做迁移、双读、转发或 fallback；当前结构的健壮性不判断来源版本。清理旧兼容不改变上述长期能力，除非用户明确要求调整对应结构策略。

## 部署与 CI

- Compose 中 PostgreSQL / Redis 只保留主版本游标，不固定小版本或 digest。运行数据目录不进入 Git 或构建上下文。
- `ADMIN_USERNAME` / `ADMIN_PASSWORD` 只用于首次创建管理员（语义见[数据库](database.md#管理员)），直接放在服务 environment；数据库与管理员密码不写入 `config.json`。Redis 内存上限与淘汰策略由部署方管理。
- GitHub Actions 只负责 dev / release tag、版本核对、生产镜像构建分发与 GitHub Release，不运行本地门禁，远端成功不能替代本地验收。公开 Action 使用稳定主版本标签，不固定完整提交 SHA；升级主版本须核对 release notes、权限和输入变化。job 不设项目自定义总运行时限，连接和请求使用协议级超时、有限重试和取消信号。
