# 存储

修改存储后端、driver、对象写入 / 删除、迁移、检查维护或临时文件时读取。

## 后端、命名空间与 driver

- 后端是按 slug 命名的实例，同一类型可注册多个；每张图片记录自己的 `storage_slug`，读取、删除都按该图所属后端解析配置与 driver。
- 物理命名空间 identity：S3 由规范化 endpoint、bucket、root path 决定，local 由运行时存储目录决定；凭据、region、path-style、公开 URL 与超时不参与。identity 相同的 slug 指向同一位置：迁移只切换数据库归属，不复制或删除对象；检查与维护按物理命名空间合并引用、只列举一次，不能因逻辑别名不同删除仍被引用的对象，但每个仍有图片的 slug 另用自身 driver 探测可读性，不能由可用别名掩盖故障。
- bucket / root path 是物理布局：仍有图片、active canonical 或未解决 `move.cleanup` 时禁止修改，并在独占位置锁内重验。
- S3 endpoint 可在使用中修改，但须在独占位置锁内证明新地址是同一命名空间的访问别名（既有对象有界 Range 读取、双向随机挑战、精确清理探针、上传校验自检）。成功后合并所有相交后端的 identity 集合，保持别名关系传递；已与他人共享 identity 的空后端也不能无证明地脱离。验证失败不写配置；COMMIT 回包丢失时按事务 ID 查询最终状态，仍未知则明确要求刷新，不能宣称旧配置必然保留。
- driver 连接签名由凭据、endpoint、region、bucket、root path、path-style 与请求时限组成。只有签名变化或删除后端才替换 driver：发布新快照时原子切换，旧 driver 拒绝新操作，已有请求和对象流排空后只关闭一次底层 client。显示名、启停、默认项、排序和公开 URL 只刷新注册表快照，不取独占位置锁、不做远端探测、不退役 driver。
- 删除后端须没有图片、active canonical 和未解决 `move.cleanup`；最终删除在独占位置锁内重读这些引用，Redis 不可用或读取不稳定时 fail closed。删除策略（动作与阻断原因）由服务端给出，前端直接渲染。
- 停用限制写入（新图片与迁移目标），并让该后端退出检查与维护；已有图片仍可读可迁出；local 只有在另一已启用后端为默认时才可停用。
- S3 能力（是否支持 Content-MD5）由服务端探测并保存在 `storage_backend.config.capabilities`，不属于 `config.json`：正确 MD5 必须成功、错误 MD5 必须返回 `BadDigest` 才算支持；只有测试连接与当前已保存连接相同时才回写；未取得结果时使用写后回读。SDK 请求 / 响应校验固定 `WHEN_REQUIRED`。
- S3 secret 明文存库但从不回传前端；编辑时未重新输入则省略该字段，由服务端合并保留。

## 注册表缓存

- 注册表唯一持有进程内存储配置快照（带期限）。应用内所有存储写入（含写入或提交回执丢失）都主动失效；重新加载前后 revision 一致才发布，失效前开始的迟到结果不能覆盖新配置。
- 直接手工修改 `storage_backend` 不会触发失效：需要重启，或等待快照到期。
- 公开与内部加载分别合并活动任务、共用同一快照；公开结果有后端数量上限，冷、热缓存都执行。

## 正式写入、guard 与删除租约

- prepare 保存三档各自的 MD5、SHA-256、体积和尺寸。commit 在单图锁内预检三个正式目标：缺失可写；既存对象必须与清单强摘要完全一致，否则 `storage_object_conflict`，且不被 guard 接管。
- 写任何正式键前，先为确定的键登记持久 `move.cleanup` candidate guard（local 原子候选的 `.candidate-<token>` 键一并登记），进程在发布前后崩溃也不会遗留无主文件。本次 attempt 只能按唯一 token 旁路自己的 guard；写入或 PG 失败由 handler 删除无引用候选，PG 引用建立后保留正式键。
- 未解决（pending、running、任意 failed）的 `move.cleanup` 是对应 identity、前缀与键的持久删除租约：所有正式写入路径在其终结前拒绝采用同一键，封闭“远端 DELETE 已发出、执行者失锁、后继重新采用”的窗口。租约还沿清理后端当前仍成立的共享命名空间关系传播。
- S3 `PutObject` 发出前，在 guard 中持久化覆盖请求、回读与远端结算的不确定窗口截止时间；确认成功后解除，失败或结果不明从失败时刻延长。handler 取得单图锁后重读最新 payload，避免按领取时的旧窗口把尚未可见的迟到对象当作已清理。
- 完整性：已确认支持 Content-MD5 的 S3 通过 PUT 校验上传正文；其余 S3 与 local 写后回读大小和 SHA-256。不能凭对象存在跳过校验。
- local 正式候选在发布前同步文件，发布及清理后同步目录与父目录链；接管既有目标、复用迁移目标、删除恢复副本前须确认 local 目标已持久化，同步失败明确失败并保留恢复来源。目录同步只在 Linux 生产镜像执行，Windows 开发环境仅同步文件。

## 迁移

- 迁移逐档以数据库登记的体积与 MD5 为期望值，任何档位缺失或不一致都停止切换，不在移动路径重新生成。同一访问身份的 S3 / COS 可在源流校验后发出带源 ETag 条件的 `CopyObject`；其他组合用恒定内存的跨 driver 流式传输。目标已存在时仍分别读取源与目标的强摘要。
- 传输验证通过后才以旧位置做 CAS，并在同一事务写入 revision 与源对象清理凭据。COMMIT 结果不确定时持锁重读：已指向目标则采用目标并确保源清理任务存在；仍指向源则只追踪目标候选；位置未知则保留两端并记录结构化错误。补偿只处理本次实际创建或事务明确转交的对象。
- 单图、所选图片与整后端迁移复用同一个单图原语和同一个逐图并发容量 owner，不建第二套执行器、阶段 DTO 或补偿协议；不持有覆盖整个批次的长事务；整后端按 UUID keyset 分页，绝不一次加载整个后端。一个成员失败不回滚其他成员；客户端断开会中止当前并发片并等待候选与清理所有权收口。整后端错误以 `error_count` 为权威总数，样本有上限；消费者只能按 `code` 判断，不得解析 `message`。
- 迁移目标必须已启用，服务端在请求入口和逐图执行边界都重新校验。

## move.cleanup 执行

- payload 固化后端 slug、对象前缀 / 键与入队时的物理命名空间 identity，不携带对象字节。
- 执行时持单图锁，先确认 slug 仍指向原 identity，再按当前位置重读 PG 引用；对象已成为当前位置则保留。任务不读写三档事实，也不生成或采用缩略图。
- driver 报告删除成功后仍须确认对象不存在；仍存在或确认失败则持续重试，并写入含图片、后端、命名空间、键与原因的结构化错误日志，不回滚已成功的位置切换。耗尽任务仍保留删除租约与后端占用。
- 运行中再次收到同一清理请求会持久记录 rerun，当前处理成功落库时重新变为 pending，不丢失唤醒。

## 删除准入

- 清理与永久删除统一使用 provider 中性的 `removeObjects(1…N)`；每项最终为 removed、missing、failed 或 unknown。删除前后都确认对象状态，只对未收口项有限重试；已发出的调用只有删除后确认才算成功，取消只阻止后续批次启动。
- durable cleanup、检查维护与回收站删除在全进程只允许一个活动 driver 删除调用（FIFO 许可）；多个 driver 分组逐组取得许可，不预占位置；`move.cleanup` 一次只领一个，回收站逐图完成后再处理下一项，避免在共享许可前堆积持锁连接。
- 回收站删除一旦发出，就在同一单图锁内完成 metadata 条件删除，不能因取消把对象已缺失的记录恢复为可恢复状态。

## 检查与显式维护

- 只有已启用后端参与检查与维护：列举、可读性探测、档位维修的目标与来源、删除候选都只取已启用后端，停用后端不产生存储请求。原因：停用后端可能是外部同步的备份位置，其对象按游离或跨命名空间副本处理会清空备份。物理命名空间至少有一个已启用后端才被检查，由已启用者列举；同一命名空间内停用后端登记的图片仍计入引用保护，但不检查缺失、不维修，检查结果以 `disabled_backend_images` 列出其后端与图片数（为空时省略）。从备份恢复不属于检查与维护。
- 预览接口只读，不作为执行依据。唯一写入口取得独占位置锁后重新读取 PG、Ingestion 引用与完整存储快照再生成候选；活动 canonical 的正式候选受引用保护。取消先收口已开始的工作，再释放锁。
- 列举有上限并显式返回是否完整：不完整列举永远不用于推断对象缺失；写维护只在三个档位快照都完整后才生成修复或删除候选；I/O 错误不当作空存储。不存在的本地目录才按空命名空间处理。
- 档位维修只从其他物理后端采用与登记尺寸、体积、MD5 一致且完整解码通过的同键同档副本；已有目标也须完整核验，不以键存在代替健康。没有一致副本时报告从备份恢复。永不重新编码、覆盖损坏对象或改写登记事实。维修写入已被引用的位置，不登记孤儿删除；写后确认失败时保留目标与来源，后续从数据库事实复核后才删除副本。
- 删除其他后端的同图副本前先完整核验当前位置对应档位；位置未知、内容不一致或维修失败时保留副本。已交给永久删除任务的 deleted 图片不补回缺档。
- 正常读取不做存在性探测、修复查询或同步补建；缺失返回 404，修复只能由显式维护执行。
- 本地空目录修剪使用非递归 rmdir，不删非空目录、存储根与三档根，不跟随目录软链接，受总项数预算；目录信息超出捕获预算时按当前文件树有界修剪，不以不完整事实省略扫描。

## 临时文件与读取上限

- 接入素材统一位于 `data/temp/<session>/<image>/`，用 generation 与 execution token 区分原始文件、处理结果和写入中文件；canonical 冻结 generation 与 producer token，迟到执行者不能发布或覆盖新执行者的文件。浏览器只与主站交互，接入无需配置存储桶 CORS。
- 孤儿清理为单实例周期 worker，只在 Redis 可用且 canonical 引用形成稳定有界快照时运行；只删除未被引用、无活跃精确路径租约且超过年龄门槛的文件，Redis 不可用时跳过。延迟取消清理只删除取消时冻结的精确 raw generation 与处理结果，新 incarnation 和未知遗留由年龄扫描兜底。
- 成品缓冲读取（预览、自动亮度）有独立的内存安全上限并核对登记体积；它与接入准入的 `ingestion.max_file_size_mb` 分离，降低准入上限不影响已有成品读取。超过缓冲上限的对象仍可流式读取。
