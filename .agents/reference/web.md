# Web 约束

修改前端查询、路由状态、公开浏览、展映、弹窗交互、分块或样式时读取。

## 查询与写入

- 同一资源只有一个查询 owner；路由返回、Strict Mode、窗口聚焦、弹窗开关与写操作结束都不能制造第二个 owner，写操作结束只做一次必要失效。新增读取前先找到现有 owner。
- 分组成员写入结果未知时先用有界读取等待同组写锁，该读取不依赖页面挂载；确认写入结束后刷新图片查询，再刷新分组计数，不失效公开图片或普通后台图片列表；图片字段修改、回收与存储变化同时覆盖分组图片查询。分组成员页与挑选页共用现有分页和选择所有者，范围进入独立查询键。
- 分组随机链接条件独立于页面筛选，不保存到分组；自动设备省略 device 与 fallback，条件外标记只依据当前页条目与共享 UA 规则。图库挑选允许选择与连选全部条目，加入与移出分别从当前选择中取未入组与已入组项。
- 按 ID 分组操作在快照读取时核查目标分组成员关系，加入排除已入组项、移出排除未入组项，并在输入窗口说明原因；只将可操作图片交给预览，不从当前分页推断任意 ID 的成员状态。解析结果不代替提交时的服务端校验。
- 图片 mutation 的失效：当前后台列表是必须确认的刷新，其余投影尽力失效；通用失效函数不接收页面专用的 query-key 特判参数。
- 写结果未知时沿同一锁边界读取权威快照收敛，不重放 mutation，不从卡片消失反推成功。读取类请求才使用有限重试；写请求只有单次期限，超时不代表服务端未执行。
- 权威快照到达后立即结束编辑器的保存等待；派生查询在原 owner 后台刷新，其挂起或失败不阻塞编辑器。
- 图片编辑器始终是数量中性的 `items` 会话（单图即一个成员）；公开详情与后台共用同一 mutation、快照与会话能力，不建第二个公开查询 owner，也不另写单图分支。按 ID 删除与按 ID 分组成员用途是同一会话的只读展现，复用预览、分页与字段展现，底部按用途执行删除、加入或移出；成员写入与刷新仍由分组页面持有，不另建预览；由其他弹窗交接打开时两者在同一次渲染中切换，遮罩不重新淡入。
- 后台列表在类型上包含完整编辑快照与共同详情字段，详情直接使用；原图入口按 `original` 的真值由客户端拼接，列表的原始地址与概览 / 公开详情的布尔标记共用这一判断。编辑入口明确传完整对象或 ID，不靠探测字段猜测来源。完整对象不追加快照读取；只有 ID 的入口继续由既有快照读取者补齐。完整对象的准备结果复用须确认对象引用未变，不能仅凭相同 ID 沿用旧初值；列表原有条件重验证取得 304 时可保留原对象。仅 ID 入口保持既有准备窗口，不按全局数据修订追加读取；这些机制不提供每次打开前的服务端新鲜度保证。
- 唯一 JSON 客户端拒绝成功响应中的 HTML、空正文或截断 JSON，不把解析失败写入查询缓存；凭据与 401 处理集中在同一请求边界。

## 路由与 URL

- 公开筛选值只接受 slug；显示名只用于 facets 展示和控件联想，不把 URL 或后台手输 slug 映射为显示名同形的其他词条。
- 画廊 / 展映的 URL 是筛选状态的唯一来源。只写用户实际操作的参数（筛选、`order`、`mode` 各自独立），省略的参数跟随站点默认，读取默认值不回写 URL；内部数据身份与请求使用解析后的值。
- 跨页导航只携带目标页面支持的显式选择，保留待修复的筛选原值；画廊链接不携带展映 mode / group。星群分享按实际画面生成，不把暂存但未生效的筛选写进页面或随机图链接。
- `device`：缺省为全部设备，随机链接显式写 `device=all`；`auto` 保存为路由状态，在建立列表请求与 query key 前用 shared UA 规则投影为 `pc`、`mb` 或无条件，随机链接省略 `device`。公开缓存响应不依赖隐含 User-Agent。
- 合法条件形成前不发送扩大范围的图片请求，也不生成随机或分享链接；非法、未知或超限条件保留原 URL，提供逐字段清除。
- 画廊历史恢复只保留最近一个历史条目，仅浏览器前进 / 后退且条目匹配时恢复；主动导航（包括已在画廊再次点击画廊）重新读取并回到顶部。同一页面实例内的 mutation 使历史返回时重取受影响数据；不跨标签页广播失效。
- 画廊列表等待 HTTP 条件重验证后再使用缓存，不先显示旧列表，保证一次主动刷新就能移除已删除图片。

## 公开浏览数据

- 公开列表投影保持最小：展映只有身份、标题、地址引用与 small 宽高，画廊另加主题与标签 slug；其他字段由详情补齐。详情首帧比例取自列表宽高，详情不重复返回宽高或三档事实。
- 显示名与词表顺序由会话级 facets 在客户端映射，列表页与筛选统计只返回 slug，服务端不重复投影词表；同时依赖统计与 facets 的视图等两者都到达再显示，首次显示不出现名称或顺序切换。
- 统计比会话 facets 新：统计出现 facets 未包含的成员时，由统计查询重新校验一次 facets（同一组缺失成员持续存在时只触发一次），其间新成员以 slug 暂列末尾；改名不改变成员，刷新后生效。已加载的 facets 能解析全部所选标签时，后台刷新失败不阻断画廊与展映；首页已有 facets 时同样不显示目录读取失败。
- 公开详情要求显式 `view`，服务端共用记录查询与缓存，只按视图投影。单图详情直接返回 `base_url`：打开前图片可能已迁移，前端必须采用详情的最新地址。详情查询键包含图片 ID、会话身份与视图。
- 批量图片响应返回 `base_urls` 地址表，条目以 id、档位与 `base_index` 拼接 URL（单根省略索引，没有正式图片时省略整个表）；每页或每条 SSE 消息先绑定自己的地址表再合并。
- 图片加载失败只显示损坏状态，不切换备用地址、不追加 cache-busting 重试；完整图失败只提供显式重试。
- 画廊数据窗口与展映数据池有 DTO、DOM、纹理、像素与并发预算；容量不足时等待引用释放，不扩大预算。

## 展映

- 展映只有一个 WebGL 渲染器、ticker 与纹理缓存；渲染器直接创建，不经 Pixi `Application` 的自动选择，后者会把 WebGPU 与 Canvas 渲染器打进展映代码，而展映只按 WebGL 实现。无法初始化时显示需要 WebGL 的说明，浏览器给出的原因只写入控制台，画廊按启用与回退规则显示时提供带当前筛选和排序的画廊入口（嵌入展映进入嵌入画廊），不自动跳转。场景切换保留预算内纹理，路由卸载释放全部资源。图片几何、动画与命中不进入 React 逐帧 reconciliation；关闭 Pixi 自动无障碍，键盘与读屏由有界 DOM 代理提供。网络失败按 URL / 来源暂停，只在联网恢复或用户恢复播放时重试，不逐帧重试。
- small 的压缩图片字节与解码纹理由同一缓存持有：按完整资源 URL 合并在途下载，并在独立字节与条目预算内 LRU 复用；纹理仍按 URL 与目标尺寸持有，字节复用不扩大 GPU 预算或改变解码画质。加载租约仅在整缓存卸载时取消，所以各尺寸可共享首次加载的取消信号；若以后增加逐租约下载取消，必须同时调整共享下载所有权。解码失败移除字节，显式恢复不能复用已知损坏的内容；路由卸载清空两层。
- Pixi 约束：对场景内的对象调用 `generateTexture` 会把它变成 render group，之后祖先透明度会被再乘一次，快照后必须 `disableRenderGroup()`；仍被渲染的 Graphics 引用已销毁的纹理时，Pixi 每帧抛错并冻结画面，纹理只能在不再有对象引用后销毁。

## 星群

- 星群（`mode=cluster`）不消费展映的单一图片流，也不叠加访客筛选：每个星团是一条只带单一分类条件的公开列表游标流，`useShowClusters` 是这些流与管理确认结果的唯一所有者；分组是访客的 URL 选择，不是站点配置。不属于当前 dataKey 的星群不交给场景。
- 部分分类或续页失败必须提供显式恢复入口，已有图片不构成隐藏故障的理由；显式重试只重新排入失败的分类流，保留已展示图片、游标与管理确认结果。
- 场景复用 `ShowPixiCard` 与同一纹理缓存；换分类与换图都只发生在看不见的位置（换位点附近渐隐、转到背面或视口外），画面上看不到切换。几何、轮换、保留预算、输入与导航的具体规则及原因见 `pages/show/useShowClusters.ts`、`show-cluster-layout.ts` 与 `pixi/show-pixi-cluster-scene.ts` 的注释，以源码为准。

## 按需加载与分块

- 冷启动资源按公开、后台登录、图片管理员、超级管理员四层划分：公开入口不打入后台实现，图片管理员不预载超级管理员能力，直接访问无权 URL 也先完成页面权限过滤。
- 预加载（hover、focus、pointerdown 意图）只取得 JS / CSS 静态闭包，不挂载组件、不发查询；同一路由的多个入口共用一个模块 Promise；失败后的导航不复用失败的动态导入。
- 分块只由导入图和懒加载处的声明决定，文件所在目录不影响分块，目录按架构职责组织。规则与常量在 `packages/web/vite-chunk-plan.ts`：先按支配关系零浪费放置（模块进入其所有懒加载根都必经的那个根，应用与第三方代码各成单位），再两两合并直到不再节省；一个单位经第三个单位才能到达另一个时两者不合并，否则合并块与第三块互相导入，模块可能读到尚未初始化的绑定，门禁也检查块导入无环。一个根加载的除了它的代码所在的块，还有这些块静态导入的块（块的导入整体执行，不论根用到其中哪个模块）；合并后两部分的根都加载合并块及它导入的块，被连带的块按新增的加载根计代价，也计入多下载上限。成本按浏览器缓存分两部分计：首次访问下载全部字节，每个输出文件另计请求头（同时含脚本与样式的单位输出两个文件），并让每份文档内联的导入映射多一条，随所有页面的首次访问与发版后回访下载；发版后回访只下载变化了的块的脚本。块之间按稳定名互相导入，文档内联的导入映射（Vite `build.chunkImportMap`）把稳定名映射到当前文件，块的文件名只随自身内容变化，不再随它导入或预加载列出的块连锁变化；发版改的是应用代码，因此含应用代码的块按会变计，第三方块不变，第三方代码并入应用块后随每次发版重新下载。
- 权限不随合并放宽：合并只在同一代码权限层内进行。从公开代码懒加载、只有管理员才会触发的能力，以及超级管理员专属的路由和能力，必须在 import 处声明 `/* @chunk access: admin|image|super */`；未声明的懒加载根取其所有前置根（静态包含或动态导入它的根）中最低的一层，只由管理员代码打开的根因此不会归入公开层。声明以 `@chunk` 开头，写成紧贴字面量路径之前的单条块注释，由 Vite 导出的解析器 `parseSync` 定位动态导入与注释，不靠文本扫描。以 `@chunk` 开头（含大小写写错或文档注释写法）却不在这个位置的注释、懒加载调用内提到 access / visits / document 却没有 `@chunk` 的注释、每项不是“键、一个半角冒号、值”、键或值写错与重复、同一目标的声明不一致，以及带权限声明的模块被权限更低的根静态导入，都会让构建失败，漏写或拼错标记因此不会静默丢掉权限层。后台页面表里的权限只管路由，需要超级管理员的页面还须在 import 处声明 `@chunk access: super`；完全漏写声明会让其共享代码按低权限层合并，门禁按独立清单兜底。
- 访问权重与份额是用户确定的取舍依据而非测量，数值在源码中：公开页最高，后台常用页（概览、图片、接入、编辑器、词表、分组）次之，超级管理员的设置类页面更低，`/* @chunk visits: occasional */`（检查、按 ID 输入）与 `/* @chunk visits: rare */`（日志、账号、登录验证码）按声明计，声明的值不再乘所在层；懒加载根的人群按导入它的上下文取更高权限的一方。一个根的加载次数取自身访问量与它自己的代码直接打开的根的加载次数之和中较大者；多个页面都会打开的功能块在这些页面的访问之内加载，不再给支配它的根增加访问。管理员几乎总带着缓存，其访问只按一部分计首次访问（入口等根随管理员页面加载的部分同样如此），后台冷启动因此让位于公开页；发版后回访只按访问量的一小部分计，足以让 React、Pixi 等大的第三方块始终独立，又不为缓存牺牲访客的首次访问。规划只按各页面直接打开计成本，不假设进入顺序。单个根因合并累计多下载的字节有上限，避免为一方的少量收益让另一方多下载大块代码；上限按根计，一个页面实际承担其必经各根的累计。
- 样式随所在块加载，权限同样单向：公开的代码与样式可以随合并出现在后台页面，图片管理员的可以出现在超级管理员页面，反向不行。因此后台样式不能依赖公开样式缺席，后台元素需要的外观由后台规则以足够特异度写明；跨文件同特异度冲突的结果取决于加载先后，需要确定结果的规则用更高特异度写明（如滚动隐藏的导航条不接受指针）。分块变化后用计算样式对比工具在桌面与手机视口核对页面。
- 缓存：静态资源按内容哈希命名、一年不可变，同一版本回访不下载代码。导入映射由服务端内联进每份 SPA 文档：键与值都按 `site.assets_base_url` 改写成与文档其他资源一致的地址（相对键会随文档路径解析到错误目录），CSP 的 `script-src` 按映射文本的 SHA-256 放行它，映射排在任何模块脚本与 modulepreload 之前。映射随每份文档下载，换来发版后只重新下载内容变了的块；只含样式的块被 Vite 移除后，映射仍保留其脚本条目，无人引用、无害。映射的键取自块名或 facade 模块名：规划命名的块按工作区相对路径计算，各机器一致；入口块的键取自 HTML 入口的绝对路径，不同构建目录（如本机与镜像）得到不同的入口稳定名及引用它的块的文件名，同一目录的跨版本构建保持稳定。Vite 注入的预加载辅助等 `\0` 虚拟模块按第三方代码处理；只按冷启动计成本时，规划会把 `vendor` 并入入口、Pixi 并入展映块，两块从此随每次发版重新下载，所以成本必须计入发版后回访。内容完全重复的资产使门禁失败。
- 样式按 Vite 内联 `@import` 后的全文计量（构建结束时样式模块已被清空，磁盘原文不含被导入的文件），汇总多份样式的文件不会被当成小样式。小文件：低于源码阈值的产物由同一成本决定是否合并，不另设名单或特判。根自己的小样式可按成本上移到同层、已有样式的直接支配根：根省一个请求，父根的其他页面多下载这些样式。小应用部分与它的第三方部分合并同理：合并后第三方代码随应用代码每次发版重新下载。Rolldown 的运行时模块不经过分组函数，始终单独成块（跨版本不变）。每个单位在创建时定名并在合并中沿用：懒加载根拥有的块用根的文件名（第三方部分加 `-vendor`，入口的为 `vendor`），共用块只分 `common`（访客也会加载）与 `shared`（只有管理员加载），包括派生的 `-vendor` 名在内统一去重，同名文件由内容哈希区分并负责缓存失效；打包器会不分权限层地合并同名分组，名字也不能按合并后的内容重新推断。业务代码不手写资源文件名。
- 文档预加载：路由页面的懒加载处声明 `/* @chunk document: home|gallery|show|embed|admin */`，构建输出各文档页面在入口之外的文件，服务端按路径在 SPA 文档中加入 modulepreload 与样式 preload，入口执行时随即开始加载当前页面，首次渲染在它就绪（或失败）后进行，页面组件用 `use()` 同步读取已就绪的模块，首屏不提交加载屏，也就没有 React 对 Suspense 揭示的 300 ms 节流。首屏加载与页面组件读取同一个保留失败的 Promise：Vite 不再请求本文档已尝试过的样式，失败后再导入一次可能渲染出缺样式的页面，失败须交给路由的错误边界。路由、首屏加载与服务端文档预加载按同一启用与回退规则（`publicPageTarget`）确定路径实际显示的页面，关闭的页面不先下载再跳转；嵌入关闭时不注册嵌入布局，`/embed/*` 按未知路径回退，嵌入开启时回退到其他页面的嵌入路径也不经过嵌入布局。等待期间显示 `index.html` 的 `#root` 里自带的加载屏（与 `AppLoadingScreen` 同结构；此时颜色域未定，公开文档带 `app-public-loading` 取公开页加载色，服务端为后台文档去掉该类，保持启动文字色），慢速网络下文档一到就有提示，首次渲染时被替换；不能用顶层 await 等待，入口块与页面块互相导入会死锁。后台文档只预加载登录前入口与 `/auth/me`（`as="fetch"` 同源凭据，由会话所有者的同一查询配置读取时复用）；公开页带会话提示时也在入口提前读取，但首屏不等它，会话所有者接上在途的读取，所以这次读取按所有者自己的重试设置，后台首屏等待它、失败后由外壳挂载时重读，因此不重试。首屏在会话读取后加载该会话首先显示的内容：未登录为登录页，已登录先取得工作区，再由工作区按地址与权限取得当前页面，都就绪后才渲染。工作区与当前页面不并行：页面的 import 留在工作区闭包内，登录页不含后台页面表，工作区仍是各页面的必经根，分块据此合并；会话确认前也不下载任何登录后的代码。工作区的页面表（地址、模块、所需权限）同时用于注册路由与首屏选择页面。
- 图片来源预连接：首页、画廊、展映（含嵌入）的文档按已启用存储后端最近一次发布的公开地址，预连接站点以外的图片来源（停用后端可能是外部备份位置，不列出），展映的纹理是匿名跨源请求，用 `crossorigin` 连接，其余页面用普通连接。文档不为此读取数据库，注册表首次加载前省略；预连接随存储公开地址变化进入文档缓存与 ETag。
- ALTCHA Worker 必须通过独立 URL 创建，只在出现登录挑战时加载，固定主站同源。
- 构建使用相对 `base`；HTML 入口与预加载地址在 SPA 文档生成时按 `site.assets_base_url` 注入，JS / CSS 字节不随 Host 改写，不需要按部署重建镜像。
- 静态预压缩的 br / zstd / gzip 各自只在严格变小时采用，不设最低体积门槛；根 `index.html` 在运行时注入配置，不预压缩。

## 交互共享边界

- 永久删除进度只来自服务端推送的全局待删数量，不以请求返回、计时或卡片消失判断完成：确认弹窗提交后显示进度，可转入后台；转入后台或页面挂载时仍有待删任务，由页头副标题常驻显示，归零后刷新列表并给出一次结果反馈。弹窗与页面各持有自己的跟随流，弹窗流在回执之后打开，避免读到提交前的状态；转入后台的删除即使在页面流首个状态前结束，也照常刷新并反馈。两条流看同一全局状态，同一次归零只结算一次：弹窗仍在跟随时后台流不结算，弹窗跟随到最终状态后确认后台流的当前完成；弹窗计数为已处理数，分母只随新加入的工作增长。失败数是回收站全局数量，结果提示按全局表述，不归属到本次请求。后台先删存储对象再删记录，`purge_pending` 卡片显示占位而不请求缩略图。
- 支持范围为 Chrome / Edge 119、Firefox 124、Safari 17.4（含 iOS）及以上，由现用运行时 API 的最低版本决定（`Promise.withResolvers`、`AbortSignal.any`）；语法与 CSS 由构建按 Vite 默认目标转换，不限制该范围。新增运行时 API 前核对其支持版本，超出范围时改用范围内的写法，并在 TODO 原生替换候选中登记以后改回。
- 支持范围内的浏览器基线 API 直接使用，不做存在性探测或降级分支；测试环境缺少的对象由测试支撑提供，不为测试保留生产分支。只有非安全上下文才缺失、类型本身可空或超出基线的能力（如特定性能条目类型），以及已弃用的兼容复制路径，保留能力探测。
- 弹窗使用单一顶层 portal 与引用计数的页面锁（`#root` inert / aria-hidden）；页面与角色模块不得建立第二套 body 锁、滚动锁或焦点管理。按需加载的弹窗模块在挂载前由发起方取得同一页面锁（上传 / 导入、按 ID 指定图片），按钮外观不变，挂载后由弹窗自身的锁接替，加载失败时焦点还给入口按钮。编辑器与详情的准备等待仍禁用其他入口：编辑器准备含网络请求，且详情弹窗内会打开编辑器，根节点锁覆盖不到弹窗内部。
- 触控直接激活按钮只用于会同步关闭、移除、禁用或重排触控表面的动作；焦点策略集中在共享按钮，不在工作流页面补定时器或坐标特判。不用延时器掩盖闪烁或状态竞态。
- 页面生命周期模块加载失败后指引整页刷新；按 ID 弹窗只有在交接中断时提示关闭后重试，不把模块加载失败提示为局部重试。
- 媒体查询只把需要改变结构或行为的条件带入 React，纯视觉差异留给 CSS。
- 带校验的输入统一用「`aria-invalid` 红框 + `FieldError` 说明」，不另写错误样式。服务端由请求 schema 校验（`parse()` 与站点配置保存）产生的 `validation_error` 以 `details.issues`（完整字段路径）给出全部问题，其余手写的 `validation_error` 没有 `details.issues`（个别公开筛选错误只带 `details.field`，页面回落到 message）；页面用 `apiValidationIssues` 读取并对应到自己的输入框，对应不上的问题写在页面反馈或窗口内；消息不拼接内部路径，字段名由页面换成界面名称。
- 后台页面通知只有一个位置：页头副标题（`ActionFeedbackRegion`），有消息时临时替换副标题；没有悬浮气泡或兜底浮层，每个投递消息的目标都必须有页面上的反馈区。弹窗内、字段校验与多态按钮的反馈留在原位，因为副标题在弹窗下不可见、字段错误要紧贴字段。排序值输入是例外：条目排序与新建表单的排序越界都只标红框、不显示 `FieldError`，允许范围写在页头副标题，因为排序框窄且位于列表行或单行表单中，下方没有容纳说明的位置。
- 后台页头固定。窄屏带操作区的页面（`.workspace-has-toolbar`）由整个工作区原生滚动：标题区（`data-workspace-pinned`）吸顶，唯一的 `.workspace-toolbar` 以 sticky top 吸在标题区下沿、位于从标题区下沿开始的绝对定位轨道内，翻页栏吸底。`useWorkspaceToolbarCollapse` 只在滑动方向改变时调整轨道下沿（下滑推走、上滑露出），逐帧移动交给浏览器，因为 iOS 惯性滚动不在主线程上运行。这些页面隐藏会画过吸顶标题区的原生滚动指示条，改用从标题区下沿开始的 `WorkspaceToolbarScrollbar`。标题区与操作区必须是兄弟节点（吸顶元素不能包住操作区），桌面上的包装层用 `display: contents` 保持原布局；控件不按断点搬到别的父节点，否则横竖屏跨越断点会卸载上传窗口与弹窗状态。滚回顶部或保持锚点时用 `workspaceScrollContainer` 找实际滚动的元素。有键盘焦点、展开的菜单 / 面板或页面锁定时操作区完整显示，焦点进入未完全显示的操作区时显示，完全隐藏时让出指针焦点。
- 可切换布局的编辑项（如词表卡片 / 列表）由同一个按身份稳定的组件实例持有草稿、输入与异步反馈，切换只改变展现；不分别挂载两套编辑器，不靠重新初始化、延时恢复或复制草稿掩盖卸载。表格库只装配列与单元格，查询、业务排序和分页仍由页面现有 owner 负责。

## 样式与颜色

- 颜色值只在语义颜色契约源（semantic-colors 系列与 token 声明）中声明；页面和组件只消费语义 token 或上下文别名。token 按视觉职责与状态命名，不写色相，不按页面或流程阶段建色板；需要区分时使用 `soft` / `subtle` / `strong` 强度。
- 公开与后台颜色上下文独立：公开页及其中的管理弹窗始终使用公开暗色；后台色契约随管理能力块懒加载，不能依赖用户曾访问后台。
- 通用上下文别名的默认值就是暗色基线，启动阶段与公开域直接沿用，只有后台颜色域覆写；不另设浅色公开控件色。公开组件即使没有页面级覆写，也必须落在暗色反馈、缩略图、滚动条与正文颜色上。
- 公开与后台共用的组件（如移动导航）用后台可覆写的别名取色：别名只由后台域定义，其他地方以 `var(别名, var(公开 token))` 在元素上读取公开 token，页面容器上的公开覆写照常生效；后台不得依赖公开样式未加载，因为合并后公开样式可以出现在后台页面。
- 悬停（含菜单键盘定位）与选中是两个独立角色：悬停只用中性悬停色，已选中继续使用选择强调色；悬停色不复用任何表面底色，调整底色时不连带削弱悬停或改变选中反馈。
- 后台页面操作区（页头操作组、工具栏与新建表单）中的输入框、下拉框与文字按钮共用 `--admin-control-height`，桌面与窄屏同值，并用 `height` 固定：内容撑开的高度随字体行高变化，同排控件会出现半像素到数像素的差。工具栏与新建表单内控件之间、各行之间共用 `--admin-control-gap`（页头操作组与其下工具栏行之间、桌面页头换行处仍是页头自身的分组间距），页头标题行共用 `--admin-title-row-height`（桌面与控件同高，使标题与右侧按钮中线对齐）；列表与操作区之间是控件间距加滚动区内的 `--admin-list-safe-area`，安全区放在滚动容器内部，卡片悬浮上移或阴影不被裁切；断点差异只在变量上声明，页面规则不按断点各写一份尺寸或间距。带边框的组合控件（筛选条、视图切换、复制链接框）以外框为准，内部按钮随外框拉伸。状态切换、窄屏标题行切换、窄屏导航按钮、卡片与列表行内控件及弹窗按钮各有尺寸层级，不使用该值。
- 颜色门禁只校验语法、token 定义与引用完整性、启动文字对比度和公开 / 后台依赖边界，不维护状态词黑名单或文件例外清单；命名与视觉由审查和用户核查判断。具体色值属于用户核查结果，以源码为准。

## 验收边界

- 桌面注入合成安全区、移动 Chromium 或桌面 WebKit 手机尺寸只能证明 DOM、CSS、事件与焦点契约，不能代替真实 iPhone Safari 的工具栏、裁切与视口验收。模拟 DOM 测试不承担真实排版或 GPU 结论。
