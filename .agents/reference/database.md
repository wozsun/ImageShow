# 数据库

修改 schema、SQL、readiness、回收站、词表或图片编辑事务时读取。表结构与约束以 `packages/server/schema.sql` 为准。

## 结构维护与 readiness

- `schema.sql` 完整定义当前版本的干净安装结构。空库（系统目录中没有任何用户关系）在同一事务中执行 schema 与只读 readiness，失败回滚；非空库只做最小只读 readiness，不执行 DDL，业务数据只核对作者身份平台在应用支持的列表内（数据库 CHECK 不枚举平台）。
- 既有数据库的结构新增、修改、删除与必要数据整理由维护者按实际变更人工处理，并明确停机、备份与恢复方案。不维护自动增量入口、编号迁移链、schema diff 引擎或版本 ledger；应用不自动补表、回填、改写原数据或对齐完整 schema。
- 临时例外（6.9.0 – 6.9.1，6.9.2 删除）：非空库在启动事务中、readiness 之前执行 `schema.sql` 中标记的 6.9 统计表一段（`core/database/temporary-schema-upgrade.ts`），只 `CREATE ... IF NOT EXISTS` 新表与索引，不修改、不读写既有对象；所有对象已存在时整段跳过，因为 PostgreSQL 对已存在的表同样检查建表权限。结构不符交给 readiness，缺少建表权限时以明确原因启动失败。该段与干净安装共用同一文本，段内语句必须保持幂等。
- readiness 只核对当前运行时实际读写所需：业务表、源码使用的列及类型、必需种子、会话可写与各表实际操作权限，以及当前 SQL 直接依赖的行为约束（按列和谓词语义核对，不依赖数据库对象名）。不使用回滚写探针。必需结构或权限不满足时明确失败。
- 额外表不读数据、不要求权限、不报错、不删除；未消费的索引、约束和允许应用省略值的列继续容忍。对应用执行 INSERT 的表，额外的 NOT NULL 且无列默认值、域默认值、identity 或生成表达式的列会阻止写入，readiness 须只读拒绝并报告列名，由维护者处理结构；不按旧字段名特判。readiness 不复制完整 schema 的可空性、默认值、无消费者 CHECK、触发器或普通索引；只有被读写直接依赖的才作为例外纳入。新增 SQL 依赖某个约束时，同步加入 readiness 的唯一契约数据源，其他检查模块不复制。
- readiness 在启动事务的同一连接上顺序执行，不对同一 client 并发 query。
- 主查询池与 advisory lock 池分离；运行期领域锁使用 advisory 池。

## 回收站与永久删除

- 图片状态只有 `ready` / `deleted`。移入回收站只改状态并退出全部公开发现入口，对象与媒体 URL 不变；回收站不是访问撤销，已知直链仍可读。恢复不搬对象。
- 永久删除在回收站成员锁内的短事务中，为当时仍为 deleted 的精确 ID 集合逐图创建幂等的 `trash.purge`。`all` 只解析事务快照，之后进入回收站的图片不属于本次范围；空数组或缺省字段不能表示全部。重复请求只计 `already_queued`，不改动已有任务的退避、错误或耗尽状态。请求断开不撤销已提交的意图。
- metadata 不保存任务字段：`purge_pending` 与“可否恢复”都由任务存在性推导；存在任何 purge 任务（包括耗尽或异常成功）即不可恢复。没有任务就没有删除意图，不从图片表反推或重建意图。
- Worker 在单图锁内核对 token、目标状态与对象位置；三档对象删除确认后，按 ID、deleted 状态与位置条件删除 metadata。对象删除开始后在锁内完成数据库收尾，不因执行期限丢弃。
- 确认请求只提交意图并立即返回回执，不等待删除。进度经 SSE 推送全局状态：仍有图片的 purge 任务中待处理（pending / running）与失败的数量，无待处理即发送最终状态并结束，所以空闲时只有一次短请求；同进程任务每完成一项即唤醒流按最小间隔重读，失败在 handler 返回后才落库，因此流在空闲间隔内也重读。PG 计数是唯一依据，前端在意图提交后才打开跟随流，首个状态必然包含本次意图。
- 目标 metadata 仍存在的 `trash.purge` 不裁剪；目标行消失后按普通历史期限处理。
- 显式存储维护可重试全部耗尽任务，并把仍有 deleted 目标的异常成功任务恢复为 pending；不为普通回收站图片创建任务，不自动删除异常 ready 目标，不接管仍在运行的任务。正常图片请求不探测任务完整性。

## 主题空值

- `metadata.theme` 可空、无默认值；SQL `NULL` / API `null` 表示无主题。字符串 `"null"` 是保留选择器，不能存为主题 slug。
- 排除普通主题时仍包含无主题图片，只有排除 `null` 才排除空值。虚拟“未设置”项只用于筛选与统计，不是词条，不可编辑、删除或排序。全量、交叉筛选与随机索引语义一致。
- 更新时省略 `theme` 表示不修改，显式 `null` 表示清空。删除主题在图片事务内把关联置空并推进 revision。
- Ingestion 的请求、动作、提交意图与语义哈希直接使用 null；null 与任意字符串 slug 是不同身份。
- `metadata.author` 可空，与 `theme` 相同：API、导入会话与 Redis 条目都以 JSON `null` 表示无作者，不存空字符串。字符串 `"null"` 是主题、作者与标签共用的保留选择器，不能存为 slug；无标签以空标签列表表示。筛选语义与主题同义；统计单独计无作者图片，各作者计数之和等于总数，与主题对称。

## 词表

- 管理列表、筛选选项与接入词表统一按 `sort_order` 降序、slug 升序；存储 `local` 固定首位且不可排序。新记录的排序值只决定自身位置，不重排已有记录，复用已有词条不移动位置。
- 标签关联与 Ingestion commit 对最终去重的 tag slug 排序后取共享 advisory lock，删除取独占锁，因此删除不能穿过并发关联或外键写入。作者关联同理（共享 slug 租约 vs 显式管理的独占锁）。
- 删除标签 / 作者在同一事务推进 revision，提交后只按实际受影响的图片精确同步；旧 revision 的按需派生索引由读取端拒绝并从 PG 重建。
- 词表变更无论成功、失败还是回执丢失，都在所属写入边界内失效词表与计数缓存，后续读取以 PG 为准。后台计数包含回收站，移入 / 恢复不改变关联数；公开首页、画廊和随机只统计 ready。
- 作者身份 `identity_provider` / `identity_id` 只由 Server 在作者事务内从严格的微博主页链接派生，链接清空或改变时同步清空 / 替换；客户端提交同名字段被严格 schema 拒绝。数据库 CHECK 不枚举平台。公共 DTO、Ingestion DTO、日志与错误不暴露原始身份列，唯一冲突只返回稳定错误码。身份换绑不改写历史图片的作者关联。

## 图片编辑

- 每张图片一个事务（metadata、必要的词条创建、完整标签替换），失败只回滚该图；实际变化推进一次 revision，纯 no-op 不推进但仍报告 updated。分类变化不改对象位置与三档事实，不创建清理回执。
- 并发编辑 last-write-wins；同图请求由锁串行，但锁不证明窗口最初读取的快照仍为最新。
- PG 已提交即成功；Redis 投影、词表或计数修复失败只记录并失效或安排重建，不能把已提交结果改成可重试的普通失败。
- 显式分类和自动设备只用事务内锁定行计算；自动亮度在事务外读取 small，并在提交前复核状态与存储位置；并发分类编辑允许后写覆盖，分类不作为对象位置判断依据。只有 driver 明确报告缺图时保留旧亮度，其他错误照常报告。

## 后台数字页

- COUNT、越界判断、目标窗口 SELECT 与标签投影在同一只读 repeatable-read 事务中完成；越界返回空 `items` 与 `total`，不静默改查最后一页。标签只为最终窗口行投影，深页不为被 OFFSET 跳过的行水合标签。事务结束后的格式化不得再借默认连接池。

## 访问统计

- `visit_event`、`random_api_hourly`、`random_api_option_hourly` 是可丢弃的原始明细，按档位裁剪：访问档（`page_view` / `page_leave`）与随机 API 的两张小时表按 `analytics.visit_retention_days`，其余交互事件按 `analytics.interaction_retention_days`；裁剪按 ctid 分批删除，不依赖 `visit_event.id`。`analytics_daily` 是永久日汇总，“日期 × 指标 × 维度（JSONB）→ 次数与访客数”，指标及其 SQL 由 `analytics/daily-metrics.ts` 定义，清空按它导出的随机 API 指标划分范围，增加汇总维度不改表结构。
- 汇总与“今天”等未汇总日期的实时计算共用同一段 SQL；某日的 `rollup` 标记行与该日汇总在同一事务写入，有标记的日期只读汇总、没有的日期从明细实时计算，二者不会重复计入。汇总按日幂等覆盖：先删除该日的汇总行再写入，停机错过的日期在明细保留期内补算；日界按 `TZ`（与图片时间相同，未设时为 UTC），改 `TZ` 后已汇总的日期不重算；`TZ` 不是有效的时区名时统计按 UTC 计算并记错误日志，不让统计查询、汇总与裁剪全部失败，也不为此让启动失败；`+08:00` 这类偏移写法同样视为无效，因为 Intl 接受它，PostgreSQL 却按符号相反的 POSIX 偏移解释。
- 来源网站只汇总非嵌入浏览，嵌入浏览归到嵌入宿主，两者不混合归因；访问时段按 `TZ` 的本地小时汇总，画廊加载页数按 shared 的 `analyticsListDepths` 分档汇总，都从明细计算、不新增采集。
- 会话浏览页数按日、按会话分档（`analyticsSessionDepths`），跨午夜的会话按日拆分；新访客按 `page_view` 的 `new_visitor` 去重，访客编号只生成一次，按日相加不会重复；加载耗时按 `analyticsTimingBuckets` 分档；视口、明暗与减少动态效果只计带这些字段的浏览，较早的明细没有它们。
- `event` 指标按事件 × 页面 × 是否嵌入计数，与 `page`、`sort`、`show_starts` 等专门指标的合计部分重复；保留它作为全部事件的通用计数：日汇总永久保留而明细会被裁剪，以后新增的报表需要某个事件的历史次数时只能从这里取。
- `collect_dropped` 不是汇总：写入所有者把上报被丢弃的次数按原因随写入周期累加到当天的行，报表直接读取存储的行；汇总重写某日时与 `raw_pruned` 一样保留它，它属于访问统计范围，清空访问统计时删除。写入失败时计数留在进程内下次再写。
- 客户端可控的值（来源与嵌入宿主、错误码、仅画廊浏览的浏览器与主版本）在汇总中每日限额，超出合并为 `*` 或丢弃；统计不记录图片 ID。浏览器主版本只对仅画廊（`support = gallery`）的浏览进入日汇总，用于判断仅画廊路径何时可以退役；其余只留在明细中供保留期内排查。随机 API 来源主机在进程内每小时限额，超出计入 `*`。单日汇总失败只记录并留待下次，不阻断其后的日期和裁剪。
- 交互档按“访问档之外的全部事件”裁剪，后续版本不再采集的事件同样到期删除。
- 随机 API 小时表另存处理耗时的总和与最大值，日汇总的最大值指标在报表中取各日最大；参数使用存在 `random_api_option_hourly`，与调用计数在同一条语句写入，二者同时保留或丢失。
- 随机 API 小时桶按 UTC 整点划分，整桶归入其开始所在的本地日期；当天按小时的序列按同一规则取桶（半小时偏移时区的标签为 00:30 这类）。跨本地日界的桶在零点后最多再写入一小时，所以某日在其结束 75 分钟后才汇总。
- 跨日不重复访客只能从明细计算，范围超出访问明细保留期时只给出日均与峰值；会话数在明细期内同样精确去重，否则按日累加。明细起点取“按保留天数推算的日期”与“最近一次裁剪到达日期的次日”中较晚者：裁剪前先在 `analytics_daily` 写一行 `raw_pruned` 标记（只留最晚的一天），调大保留天数后已删的明细不会被当作完整，单日随机 API 按小时序列同样以此判断。汇总重写某日时保留该标记；部分清空保留它，全部清空连同它一起删除。
- 清空按范围（访问统计 / 随机 API / 全部）在一个事务内删除明细与对应汇总；部分清空保留 `rollup` 标记，全部清空连标记一起删除，之后由维护重新补标空日期。

## 管理员

- 只有数据库中没有超级管理员时，首次启动才用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 创建；之后账号、密码和偏好始终以 PG 为准。
- `preferences` 只保存用户的选择（例如保存 `system` 而不保存解析出的明暗）；默认值集中在 shared，API 只返回 shared schema 认识的键。

## 图片分组

- 分组是图片集合，不是词表；成员关系在回收站保留，metadata 永久删除才由外键级联移除。后台组成员数只统计 ready，与组内图片页一致。
- 加入和移出先取得分组共享锁，再按 ID 排序取得图片锁，之后进入图片写入 fence；删除分组先取分组独占锁，再进入 fence。每图分组上限在持有图片锁的事务中按全部关系校验，含回收站关系。
- 成员变更与删除只为实际受影响的 ready 图片推进同一 projection revision，提交后沿用图片精确同步或重建策略；新建空组、改显示名及排序不触及图片投影。分组 slug 不可修改。
- 图片投影条目携带排序去重的分组 slug；成员关系与图片共用 revision、精确同步及重建。分组派生属性索引沿用现有预算与生命周期；group 计数只用于内部投影，公开统计与词表维度不消费它。
- 后台分组成员页、标记页及带目标分组的按 ID 快照在建立一致性快照前取得该组独占 advisory 锁，等待成员写入持有的共享锁结算；写响应丢失后的页面回读不能抢在原事务提交前缓存旧成员。普通后台图片列表不取得分组锁。
