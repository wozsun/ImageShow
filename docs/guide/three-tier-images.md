# 三档图片与地址协议

## 当前资源契约

内部档位、配置和 `variants` 字段、物理目录、图片路由以及随机 API 的 `size` 统一使用
`large`、`medium`、`small`；数据库列继续使用 `l_`、`m_`、`s_` 前缀。
三档都是独立 WebP 文件，键为 `<档位>/<UUID 尾两位>/<UUID>.webp`。
入库仍按大图 MD5 提示重复；三档内容相同也各自保存。详情加载 medium，标题链接打开 large，
列表与展映加载 small。读取仅访问已生成的对象，不进行实时编码。

各档质量、最低质量、长边与目标体积独立配置，WebP effort 固定为 4，见 [CONFIG](../CONFIG.md#normalize)。
新安装使用产品默认值；已有安装按 config.json 中的当前三档参数处理新图片。

## 普通图片响应地址表

随机 JSON 每图返回一个绝对 `url`，规则见[随机 API](random-api.md)。公开单图详情在 `item` 内直接返回 `base_url`，
图片身份由请求路径确定，响应不重复返回 `id`。其余正式图片响应在
最外层返回 `base_urls`，没有正式图片的响应省略该表；每个图片条目通过 `id`、所需档位与地址索引组成 URL。只有一个基础地址时
全部省略 `base_index`，默认索引为 1；多个基础地址时，每图均返回从 1 开始的索引。原顺序不变。

```json
{
  "ok": true,
  "base_urls": ["/images", "https://cdn.example.com/gallery"],
  "items": [
    {"id":"00000000-0000-7000-8000-000000000001","base_index":1,"title":"示例一","width":600,"height":400},
    {"id":"00000000-0000-7000-8000-000000000002","base_index":2,"title":"示例二","width":600,"height":400}
  ],
  "next_cursor": null
}
```

拼接为 `${base_urls[(base_index ?? 1) - 1]}/${size}/${id.slice(-2)}/${id}.webp`。
基础地址可以是主站 `/images`、本地独立域名根或包含 S3 root_path 的公开地址；各段只编码一次。
多个逻辑后端若使用同一公开根，仅保留一个地址表条目。后端没有公开地址时使用主站资源入口，
由主站按当前存储位置读取或跳转。每页或每条 SSE 消息收到后先绑定自己的地址表，再并页或排序。
公开展映列表仅返回身份、标题、图片基础地址与缩略图宽高；画廊列表在此基础上增加卡片副标题所需的主题与标签。
亮度、作者和图片时间由打开详情时补齐；设备展示由宽高推导。列表筛选与排序仍按数据库中保存的分类和图片时间生效。
公开详情要求显式 `view=show|gallery`，两者均返回亮度、作者、图片时间、描述和链接；
展映详情额外返回主题与标签，画廊详情复用列表已有的主题与标签。两种详情共用记录查询和缓存，只按视图投影响应。
预览首帧比例及设备展示从列表已有的缩略图宽高派生，
详情响应不重复返回宽高、`device` 或 `variants`。图片加载后采用自身比例。
公开单图详情不返回地址表；前端详情查询键包含请求的图片 ID、会话身份和视图，
按查询键接收当前图片详情并合并列表基础项，采用详情的最新 `base_url`，用于存储位置变化后的详情读取。
公开详情的设备展示按横竖推导；后台管理、编辑与筛选仍使用保存的设备分类，人工分类可能与横竖不同。
概览紧凑详情及管理信息中的 `variants` 仅返回各档 `byte_size`，用于存储项的总大小与逐档悬停提示。
单图管理信息接口不重复返回 `id`；请求路径与查询键确定图片身份，面板的 UUID 直接使用当前图片 ID。
后台图片列表、编辑快照及接入结果按现有消费者保留各档 `width`、`height`、`byte_size`；
后台列表及接入正式结果保留用于查重的 `large_md5`。
临时接入预览仍使用受保护的接入会话地址，不能按正式对象键访问尚未入库的文件。

## 安装与运行

新安装直接创建当前三档 schema；已有数据库在启动时执行最小只读 readiness。
应用依次取得宿主锁、加载配置、准备临时目录、初始化或核对数据库，再开放服务和启动任务。
图片处理参数变化只影响后续处理，不自动重新压缩已有对象。

部署、版本更新和备份边界见[部署说明](../DEPLOY.md#版本更新)，
数据库维护见[启动与结构契约](database.md#启动与结构契约)。
