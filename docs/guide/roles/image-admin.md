# 图片管理员指南

图片管理员对应后台 `image` 角色，负责日常图片与词表维护。该角色可以查看实例检查
结果，但不拥有会改变存储位置、永久删除数据或修改实例配置的高风险权限。

## 日常工作

- 通过本地文件执行 Upload，或通过 HTTPS URL、JSONL、微博来源执行 Import。
- 在图片列表按图库、无主题、回收站及各分类筛选，选择一张或多张图片进行编辑。
- 修改标题、设备、亮度、主题、标签、作者、来源和描述。
- 将图片移入回收站或恢复；进入回收站后不再被站点发现，但既有媒体直链仍可访问。
- 查看、新建、编辑和排序主题、标签与作者。
- 查看 PostgreSQL、Redis、图片投影与存储检查，以及“全部”中的回收站一致性结果。
- 修改自己的密码、外观和图片卡片密度偏好。

图片列表的“清空”会一次移除设备、亮度、主题、标签和作者筛选，但保留当前图库 / 无主题 /
回收站视图；随后清除选择与瞬时反馈、回到第一页并滚动到列表顶部。即使在无主题视图中看不到
先前保留的主题条件，该条件也会一起清除。五项均为空时只有“清空”不可用，筛选入口仍可打开；
页面忙碌时两者都会暂时禁用。移动端清空已展开筛选时，内部菜单会收起，外层面板保持展开。
短宽且短高的滚动面板不另设内部收起按钮，仍使用顶部“筛选”主段收起。

单图编辑、移入回收站和恢复与批量操作共用同一套 `1..N` 流程；只有窗口标题、分页和批量
默认值等展示差异。详细操作与失败收敛见[功能与流程](../flows.md#后台管理)。
图片卡片上的单图删除按钮需在同一个按钮内点击两次才会执行；第一次点击后失焦或点击其他
位置会取消确认。图库 / 无主题的批量删除也在同一个文字按钮内由“批量删除”切换为“确认删除”，
不打开弹窗；提交后单图按钮保持“删除中”，批量按钮显示“正在删除”，两处都禁止重复提交。

## 不能执行的操作

以下能力只授予超级管理员，图片管理员页面会隐藏或禁用入口，服务端也会独立返回 403：

- 单图、批量或整后端存储迁移。
- 永久删除选中图片或清空回收站。
- 删除主题、标签或作者。
- 执行存储维护、对象清理或图片缓存手动重建。
- 管理用户、存储后端、站点配置、高级配置与日志。

检查页的只读结果不等于维护授权；发现缺失缩略图、孤儿对象或缓存异常时，应把检查结果
交给超级管理员确认。权限明细与接口强制边界见[安全](../security.md)，图片对象和迁移规则
见[存储](../storage.md)。
