# 超级管理员指南

超级管理员对应后台 `super` 角色，拥有图片管理员的全部能力，并负责应用内的账号、配置、
存储与高风险维护。首次空库启动时由实例维护者通过 `ADMIN_USERNAME` 和
`ADMIN_PASSWORD` 创建第一个超级管理员。

## 应用内管理

- 完成图片管理员的全部上传 / 导入、编辑、分类、移入回收站、恢复和只读检查工作。
- 创建、重置或删除图片管理员账号；超级管理员自身不能在用户管理页被删除。
- 修改站点设置与高级配置，导入或导出由目标版本按当前能力逐项识别的配置包。
- 管理内置 local 与 S3 后端的显示名、连接测试、默认项和启停，并新增或配置 S3 后端。
- 查看应用日志与检查结果，并在明确确认后执行维护操作。

## 高风险操作

以下操作会改变对象位置、永久数据或派生状态，执行前应先阅读预览与检查结果：

- 迁移一张、多张图片或整个存储后端。
- 永久删除选中回收站图片，或使用明确的 `scope: "all"` 清空当前范围。
- 删除主题、标签或作者。
- 通过单一“存储维护”操作执行缩略图修复、无引用对象清理与持久彻底删除任务维护。
- 手动重建统一图片缓存。

永久删除回收站内容时，先点击“永久删除”，再点击“确认删除”才提交；执行中显示“正在删除”，
正常情况下弹窗会等待该范围全部删除完成。
图片管理员账号与存储后端的删除同样采用三级操作：点击卡片入口打开弹窗，点击“确认删除”后
进入最终确认状态，再点击“再次确认”才提交；最终确认按钮失焦时取消该确认状态。
精确权限与请求安全见[安全](../security.md)，维护预览、锁和对象归属见
[存储](../storage.md)。

## 高级配置与配置包

「设置 → 高级配置」可以编辑完整 `config.json`，也可以导入或导出配置包。逐项含义和修改
生效规则见[配置说明](../../CONFIG.md)。重新读取会替换尚未保存的编辑，保存前请核对确认摘要。

配置包用于复制站点配置和自定义 S3 连接，不包含站点域名、内置 local 后端、管理员、图片、
词表、后台任务或部署连接。导出的文件包含 S3 Secret Key，应作为敏感凭据保管。
导入时先查看预检摘要；同名存储后端必须另起合法 slug，不会覆盖现有后端。

配置包不是完整备份。导入失败或结果不明时，先核对配置文件和存储后端列表，再根据提示恢复
文件或重新导入；数据库与对象备份由实例维护者负责。配置交接的技术边界见
[功能与流程](../flows.md#配置缓存与-worker-的交接)。

## 与实例维护者的边界

超级管理员管理的是 ImageShow 应用内部。Docker、Compose、反向代理、宿主机目录、数据库
备份、镜像升级和故障恢复属于[实例维护者](./instance-maintainer.md)，不能通过后台页面代替。
