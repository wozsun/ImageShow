# 超级管理员指南

超级管理员对应后台 `super` 角色，拥有图片管理员的全部能力，并负责应用内的账号、配置、
存储与高风险维护。首次空库启动时由实例维护者通过 `ADMIN_USERNAME` 和
`ADMIN_PASSWORD` 创建第一个超级管理员。

## 应用内管理

- 完成图片管理员的全部上传 / 导入、编辑、分类、移入回收站、恢复和只读检查工作。
- 创建、重置或删除图片管理员账号；超级管理员自身不能在用户管理页被删除。
- 修改站点设置与高级配置，导入或导出由目标版本按当前能力逐项识别的配置包。
- 管理内置 local 与 S3 后端的显示名、连接测试、默认项和启停，并新增或配置 S3 后端。
- 查看应用日志与检查结果，并在明确确认后执行维护操作。

## 高风险操作

以下操作会改变对象位置、永久数据或派生状态，执行前应先阅读预览与检查结果：

- 迁移一张、多张图片或整个存储后端。
- 永久删除选中回收站图片，或使用明确的 `scope: "all"` 清空当前范围。
- 删除主题、标签或作者。
- 执行存储维护与确认无引用对象清理。
- 在 5.6.0 检查页执行一次性图片存储布局升级，并确认旧 `media` 引用、对象和清理任务归零。
- 手动重建统一图片缓存。

这些权限由集中能力矩阵下发，前端可见性不是授权依据；每个后端入口都会再次校验。
单图、批量与清空回收站共用一个确认弹窗：先点击“永久删除”，再点击“确认删除”才提交；
第一次使用 `delete-bin-7-line`，第二次使用 `delete-bin-2-line`，提交后以
`delete-bin-5-line` 显示“正在删除”，正常情况下弹窗会等待该范围全部删除完成。
精确权限与请求安全见[安全](../security.md)，维护预览、锁和对象归属见
[存储](../storage.md)。

## 5.6.0 布局升级

升级前停止 Upload / Import，并确保只有一个操作者使用后台；本次受控窗口允许图片直链短时
失效。打开“检查 → 升级图片布局”，先读取旧布局数量、预计传输量、旧 Ingestion、清理任务和
投影 revision，再勾选确认并开始。页面会自动执行 10 张一批的请求；断线、
刷新或关闭弹窗不会丢失已提交结果，重新打开后从 PostgreSQL 剩余旧键继续。

只有页面明确显示 100% 与“全部完成条件已由服务端确认”才能结束生产迁移。请保留这份完成
证据供 5.6.1 清理旧路由和升级代码前复核；数据库已经迁完但页面仍显示 99% 时，应等待
`move.cleanup` 和 ready-image revision 收尾；这些廉价状态收敛后页面才执行物理 `media` 终检，
而不是每个短批次重复扫描对象存储。终检仍未归零时应先运行存储维护，不能直接跳过。

## 与实例维护者的边界

超级管理员管理的是 ImageShow 应用内部。Docker、Compose、反向代理、宿主机目录、数据库
备份、镜像升级和故障恢复属于[实例维护者](./instance-maintainer.md)，不能通过后台页面代替。
