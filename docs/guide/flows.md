## 图片接入

本地文件、URL、JSONL 与公开微博进入同一 Ingestion 领域。浏览器拥有尚未接管的文件和
草稿；服务端接受任务后，由 Redis canonical 与单实例 Worker 接管。图片完成 PostgreSQL
事务后才正式入库，Redis completed 回执只用于交接和展示。

接管、prepare、commit、队列分页、取消及恢复的完整规则集中在[图片接入](ingestion.md)。
存储对象的最终位置和持久清理见[存储](storage.md)，后台入口见[图片管理员指南](roles/image-admin.md)。

## 公开浏览与图片出口

### 首页、展映、画廊与嵌入页

公开页按路由启用全面屏视口，操作层避让四向安全区；后台与登录不变。
嵌入页可接收宿主换算的实际避让尺寸，也可按宿主订阅上报原生安全区，
详见[公开页面与嵌入安全区](embed-safe-area.md)。

首页读取图库统计并以一次随机图请求取得背景；设备、明暗、主题、标签和作者选择只更新
本地状态，进入配置的画廊或展映目标时以 `device`、`brightness`、`theme`、`tag`、`author` 完整名称
写入 URL 查询参数。配置目标关闭时使用另一个仍启用的图片页，两者都关闭时入口保持不可点击；
`/embed/home` 遵循同一目标配置和回退规则，进入 `/embed/gallery` 或 `/embed/show`，保留嵌入路径。
首页主题、标签和作者目录只展示全局至少关联一张正常图片的词条，标题数量按实际返回词条计算；
主题“未设置”也遵循此规则。全局有图片、仅因当前筛选而数量为 0 的词条继续显示，沿用禁用与
已选可取消的交互。设备与明暗选项始终显示，仍按候选数量决定能否选择。
完整词表及标签合法性解析不受目录展示规则影响。
移动端目录的主题滚动区显示约 8 行半，标签显示
约 7 行半，作者显示约 6 行半，以露出的下一行提示还可继续滚动；更多内容保留在对应卡片内。
该高度只在 `760px` 及以下生效，不改变桌面目录尺寸。`/embed/home`、`/embed/show` 与 `/embed/gallery`
复用对应公开页的组件和查询，只不挂载主导航；是否允许嵌入及父页面范围由服务端配置和 CSP 决定。
嵌入展映保留筛选工具栏、双模式、详情和底部操作，筛选栏只在自动播放期间启用三秒无点击隐藏，并保留顶部 36px 唤出规则。

三个嵌入入口随 `embed.enabled` 默认提供[宿主光标桥接](embed-cursor.md)：直接父页面连接后，转发主鼠标的
位置及按键状态，由宿主绘制光标，ImageShow 隐藏内部原生光标。普通访问与未接管时保持原有行为；
协议不读取图片或账号信息，不阻止拖动、缩放、筛选和详情操作。

首页、展映和画廊分别受自身启用开关控制，主导航只呈现已启用页面。根路径优先采用配置目标；
该目标关闭时按画廊、展映、首页的稳定顺序回退。三页全部关闭时根路径直接返回 HTTP 404，
不会跳往随机图 API 或后台；`/random` 与 `/admin` 继续由各自路径提供。

画廊 URL 是筛选状态的唯一来源。“全部设备”是缺省状态，列表不附加设备条件，并让生成的
随机图链接显式使用 `device=all`；“自动设备”稳定保存为路由状态 `device=auto`。Web 使用与
Server 随机出口相同的纯 User-Agent 规则，在列表请求和 query key 建立前把自动状态投影为
`device=pc`、`device=mb` 或无设备条件，未知 User-Agent 安全展示全部设备；自动状态生成的
随机图链接省略 `device`，由 `/random` 请求边界归一为规范 `auto`。刷新、前进 / 后退和
`/embed/gallery`、`/embed/show` 都保留这个路由状态，公开缓存响应不依赖隐含 User-Agent。

主动点击画廊导航会重新读取图片列表并回到顶部，已经位于画廊时再次点击也一样；首页进入画廊
等主动导航遵循同一规则。浏览器前进、后退返回画廊时，只有最近一次保留的历史条目、查询和
实际布局匹配，才恢复对应图片及卡内偏移；不保存多条画廊历史快照，整页刷新或重新打开不恢复。
同一页面实例内的编辑、删除等操作会让历史返回时重取受影响的数据；另一标签页的改动不主动
同步到当前实例，需要点击画廊导航重新读取，浏览器历史恢复本身不保证跨标签页数据即时更新。
画廊列表请求等待 HTTP 条件重验证后再使用缓存，未变化仍可复用 304；不先显示旧列表再由
浏览器后台更新缓存，确保主动刷新一次即可移除已删除或已退出筛选的图片。

展映与画廊共用浏览工具栏，提供“筛选”、已应用条件摘要、排序与“分享”。
筛选入口在无条件时显示“筛选”，有条件时显示由分隔线隔开的“重新筛选｜清空”，两种形态保持相同总宽度。
桌面展映的缩小、放大和复原位于筛选左侧，暂停 / 继续位于分享左侧；761–900px 将模式切换收进“画面”菜单。760px 及以下顶部只保留筛选和分享，不显示条件摘要；展映左下依次为复原、放大、缩小，右下为排序、播放与画面切换。移动画廊右下为返回顶部和排序。底部控件采用方形圆角，沿用公共尺寸、配色及显隐规则。
筛选弹窗采用后台暗色配色，目录和选项区复用自有滚动条；设备选项提供不限设备、自动判断、横版图片和竖版图片；自动判断按请求者设备投影，页面链接保留 auto，随机链接省略 device。
分享菜单提供页面链接与随机 API 链接，始终使用当前已应用条件，各自可复制；菜单打开时不自动聚焦或全选链接，点击只读链接框时全选完整 URL。页面链接额外固定当前解析后的排序与展映模式，嵌入入口转换为主站对应页面并提示，不带滚动位置、暂停状态或随机批次；随机 API 链接只投影筛选条件。
筛选入口右侧的“清空”一次移除五字段，保留排序、模式和其他查询参数。

筛选按钮在桌面打开居中弹窗，在手机打开全屏弹窗；左目录定位右侧设备、明暗、主题、标签、作者五个连续区块。
目录按名称 / slug、中文全拼或首字母搜索并高亮匹配位置，不使用后台搜索的 50 项上限；主题、标签与作者只展示全图库有正常图片的词条。标签展示成员复用弹窗已有的未筛选统计，完整词表仍负责标签合法性解析，已有零匹配条件保留在已选栏并可移除。
主题与作者支持整组包含 / 排除；标签支持组内任一 / 全部，“成组”后转入新组，以 1–9 标记成员。组间为或，同一标签允许属于多组。分组摘要支持切换编辑和删除，最多 9 组（含当前编辑组），最后非空编辑组随应用提交；空组不生成查询。成组后，已选栏按非空组显示“标签 + 组编号”，组内或用 `/`、且用 `&` 连接显示名；移除按钮只删除对应整组，不影响其他组内的同名标签。未成组时仍逐标签移除，已选数量和目录数量始终按标签去重计数。
标签卡片只高亮当前编辑组的已选项；仅属于其他组的标签保持普通卡片样式并显示所属组数字，切回该组编辑时恢复高亮。
选择、移除、切换匹配方式和已选条件栏的清空只修改草稿；弹窗外的图片、摘要、随机链接与 URL 保持已应用条件。
主题和作者选项旁显示排除本类别条件后的候选数量；标签“或”模式排除所有标签条件，“且”模式保留当前编辑组的已选标签，显示继续加入候选标签后的交集数量。设备与明暗采用分段单选，数量放在悬停提示中，“不限”使用该维度候选数量之和。选项数量、非空标签组数量与底部完整匹配数共用即时预览结果，选择后直接请求，不设固定等待。组数量保留当前非标签条件，各组重叠图片在底部合并去重。更新中保留上次数量，“已选”栏下方显示一条弹窗主题蓝色的刷新光带，底部说明固定显示“应用后更新展映 / 画廊”；失败时保留已有数量并提示失败、提供重试。没有可用数量时显示未知，不伪造 0。当前候选数量为 0 的全局有效词条仍保留，未选项禁用，已选项可取消；统计更新中、失败或数量未知时暂停新增选择，仍允许移除条件和选择“不限”。
合法零匹配条件和统计暂时失败都允许应用；无效或无法校验的标签须显式清除或重读词表后处理。
点击“查看图片”或“应用到展映”后，弹窗先退场并完成页面滚动恢复，再一次写入完整筛选。
取消丢弃本次草稿；外部路由变化撤销打开的旧草稿与未完成应用，避免覆盖前进 / 后退后的状态。
展映打开弹窗期间暂停运动，关闭后保留原先播放 / 暂停意愿；不建立另一套图片查询或渲染实例。
四个公开浏览入口复用同一流程，嵌入页继续保持访客身份及安全区约束。
展映的主导航与筛选工具栏只在自动播放期间计时，三秒没有点击操作后一起隐藏。暂停播放立即取消
计时，恢复播放后重新计满三秒；加载、无图、错误、页面隐藏、减少动态效果或 WebGL 暂停时同样
停止计时。暂停本身不改变导航当前显隐状态，也不影响手动滚动的导航规则。只有点击重置空闲计时，鼠标移动、
滚轮和普通按键均不重置；仍可通过向上滚轮或移动端向下拖动唤出。桌面双模式的鼠标向上拖动
保留导航收起，向下拖动及其惯性不唤出，回到手动位移起点也不例外；触控拖动保留原有显隐规则。
导航菜单、筛选弹窗或图片详情展开期间暂停自动隐藏，关闭后仍在自动播放才重新计满三秒。
已展开的主导航或筛选工具栏内存在精细指针悬停或键盘可见焦点时，取消空闲计时，并暂停滚动触发的收起。
主导航与筛选栏作为同一交互范围，内部移动鼠标或切换焦点不会恢复计时；只有鼠标与焦点都离开，
且展映仍在自动播放、菜单、面板和详情均未阻止隐藏时，才重新计满三秒。触控设备只以键盘可见焦点
保护导航，忽略触摸残留的悬停及普通按钮焦点；筛选弹窗关闭并归还按钮焦点后，展映和画廊恢复滚动收起，展映按播放状态恢复计时。
首页主导航同样暂停滚动收起，
嵌入展映和嵌入画廊的筛选栏复用相同规则；导航以外的鼠标移动仍不重置计时。
移动端底部控件在导航存在时为 80% 不透明度，导航完全收起后先降为 30%，五秒后淡至 10%；
悬停或键盘可见焦点提高至 95%，仍可直接操作。底部操作提示在导航收起后先降至 20%，五秒后淡至 10%。
窄屏与粗指针设备同样显示提示，waterfall 为“拖动平移；点按 ± 或双指缩放”，float 为“上下拖动；点按 ± 调整尺寸”。
工具栏模式链接显示“瀑布 / 漂浮”，当前模式通过可见状态与 aria-current 标识，重复选择当前模式不新增历史记录。
画廊与嵌入画廊不启用空闲计时，只保留原有的滚动显隐、顶部恢复及交互保护规则。
展映和画廊由整组导航的一次位移带动主导航、筛选栏和共用背景，三者共同收起和展开；
滚动仍按原阶段切换，展映的计时收起则直接同步滑出整组导航。
首页、画廊与展映共用鼠标顶部唤出规则：鼠标从区域外移入浏览器内容视口顶部 36 CSS px 时，
立即显示导航；画廊与展映同时显示主导航和筛选工具栏。每次移入只触发一次，区内继续移动
不重置无点击计时，按住鼠标拖动不触发这条唤出规则。只接收真实鼠标移动或从浏览器外进入的事件，
忽略 Pixi 的合成移动和布局变化引起的内部悬停目标切换。唤出后继续按各页面的滚动显隐和播放计时规则处理；
此唤出区按视口坐标计算。

`/show` 与 `/embed/show` 复用同一展映实现，使用一个 PixiJS / WebGL Application、一个 ticker 和共享纹理预算，在两个独立场景间
切换。`mode=waterfall|float` 是正式 URL 状态；省略或无效时读取 `site.show.mode`，读取默认值不会
改写地址栏。工具栏模式控件使用真实链接，手动切换始终显式写入目标 `mode`，包括切回配置的
默认模式；链接保留当前路径和其他查询参数。修改或清空筛选、切换顺序时保留已有的显式模式，
未带 `mode` 时继续使用配置默认值而不补写该参数。React / DOM 只编排路由、导航、筛选、按钮、详情及有界键盘 / 读屏代理；
图片几何、动画和命中检测由 Pixi 运行时处理，不进入 React 逐帧 reconciliation。

进入普通或嵌入展映时，从 `site.show.autoplay` 初始化播放状态，默认 `true`；关闭时初始暂停，
仍允许按钮启停、拖动和缩放。访客手动启停不写回配置，同次挂载内切换模式或筛选不会重置启停状态；
修改配置后重新进入或刷新页面采用新值。减少动态效果、筛选 / 详情弹窗和页面后台状态继续按原规则暂停自动运动。

`waterfall` 使用相互独立的连续竖列，不建立横向行基线。ImageShow 自有窄相机直接处理鼠标和
触控 drag、wheel / pinch 缩放、惯性、中心锚点与可视边界；手动运动和缩放结束后立即按配置速度
恢复向上巡航，不增加固定等待。导航只接收相机在拖动、普通滚轮平移及惯性中实际应用的纵向位移，
拖动及其惯性携带原始指针类型，由共享导航规则决定是否允许唤出；
按钮调整大小、Ctrl + 滚轮、双指缩放及其锚点修正、窗口尺寸变化和自动巡航均不计入导航滚动采样，
不会因放大缩小而唤出或收起导航。暂停只停止自动增量。令同宽画廊列数为 `G`：最大图片为 `0.5G`，默认 `G`，普通边界 `1.5G`，最大密度
固定 `8G`，每次按钮操作增减一列。首次超过 `3G` 前显示“性能提示”，正文按以下三行固定分隔：

> 增加同屏图片数量对设备性能要求较高，<br>
> 在部分设备上可能会出现**卡顿、掉帧**现象。<br>
> 请**谨慎考虑**后决定是否继续。

弹窗按正文内容确定宽度，并限制在视口可用宽度内；窄屏空间不足时允许行内自然折行。
取消停在 `3G`，点击“继续”才应用请求的密度；
确认对本次展映页面挂载有效，筛选、模式切换和视口变化不重复提示，离开后重新进入恢复未确认状态。
按钮、Ctrl + 滚轮及双指缩放共用页面的确认状态；相机在应用越界缩放前同步取得允许值，不先显示更高密度。
弹窗复用共享焦点与页面锁，打开期间冻结导航当前显隐状态并暂停画布输入与动画，关闭后恢复原启停状态。
直到弹窗退场完成均拦截 Ctrl + 滚轮及双指缩放，避免传递到浏览器整页缩放；取消与继续按钮同色。
世界坐标可连续移动，
但只有视口缓冲内的 Sprite、纹理与 DTO 保留，回到已回收区域不承诺原图片映射。

`float` 不建立列或无限世界：卡片从当前视口下方错位进入，以受控的水平位置、尺寸和速度向上
漂浮，静态倾角上叠加幅度为 ±3°、周期约 24–40 秒的缓慢旋转，越过顶部缓冲即回收。
上下拖动、普通滚轮及其惯性可持续双向纵移：统一回收越过上下缓冲边界的卡片，从相反进入端的空档重新补入，
沿用相同候选池和纹理预取总预算。大幅手动位移拆成有界的空间步长，每段移动后处理两端回收与补图，
不先把整组卡片移出保留区。快速反向立即清除旧方向滚轮余量，拖动反向时清除相反惯性；
进入侧储备不足时，只从另一侧调配完全离开视口的卡片，优先使用已解码纹理，并保留另一侧储备。
屏内卡片不因反向重新分配位置或内容，新入场卡片与外侧回收边界保留余量，尺寸过渡中按当前与目标高度的较大值回收。
手动位移清除旧尺寸布局的纵向追赶目标；拖动、滚轮及惯性期间自动漂浮暂时让位，手动运动结束后立即按原状态继续。
暂停只停止自动上浮、横移与旋转，不停止手动位移、屏外回收、补图或纹理加载；手动操作结束后仍保持暂停。
当前只保留有限卡片与上下屏外缓冲，已回收区域重新取图，不累积历史画面。
Ctrl + 滚轮调整目标图片尺寸，不建立无限相机或缩放世界坐标。尺寸分为 `0.5×–1.5×` 的十一档，
默认 `1×`；每档实际宽度为目标宽度的 50%–130%，尺寸序列均匀穿插大小图片，大图档也保留较小
图片填补空位。数量按混合宽度的平均平方计算面积，密度系数为窄屏 0.56、宽屏 0.84，超过默认
尺寸后再按候选图片的平均竖横比例控制数量；包含屏外卡片的目标总数为窄屏 6–96 张、宽屏
8–180 张。改变尺寸时
全部卡片平滑调整大小，多余卡片在约 400ms 内渐退并释放，保留卡片平滑重新分布于整段流中，
hover / focus 中的图片保留位置；数量不足时按最大空档补位并淡入，不等待队列整体离场。

初始布局在均匀的生命周期间距附近同时选择横向和纵向位置，避让评分包含静态倾角、完整旋转与
左右漂移范围，以及图片经过屏幕中部前后的预测重叠。运行时从共享 ticker 每 80ms 最多调整一张
图片的局部水平路径，收益很小的调整保留原目标；每帧平滑改变横移速度，速度上限随尺寸为
4–10px/s，漂移幅度为 6–16px。每张卡片独立推进漂移与旋转相位，暂停、拖动或悬停时停在原位，
恢复后从原相位继续。相邻生命周期间距反馈每 500ms 缓慢调节上浮速度，
减少图片成团与空带长期同行。自动上浮与手动向上移动时，回收优先选择下方缓冲内的生命周期空档重新进入；
手动向下移动则在上方缓冲补入，两个方向共用同一回收与位置选择逻辑。
后续纹理总数以目标卡片数的三分之一向上取整，窄屏限制为 6–18 张，宽屏限制为 12–36 张，
平分为上下两条预取队列，奇数时下方多一张；反向不清空另一侧队列，也不扩大总预算。
每条队列预先确定图片与混排尺寸，对应方向补图时由卡片接管同一纹理引用，整批回收后再补足队列；
尺寸或视口改变时更新两侧所需纹理尺寸。预取与在场卡片共用既有纹理缓存、像素预算和并发上限，
重建图片集合或离开场景时释放队列引用。窄屏指视口宽度不超过 760px。
float 最多使用 500 张候选，waterfall 与页面数据流共用 800 个唯一 DTO 上限。未消费候选少于
100 张时，场景提交当前引用与已消费集合；数据流先退役已消费且无引用的候选，再续取 100 张。
空间不足时等待引用释放；超出 DTO 上限的密集槽复用现有引用，同时让最早一组候选停止领新槽并排空，
避免全部引用长期不释放。有限结果全部到齐后优先复用无引用图片。reduced-motion 下停在静态构图，不运行路径与速度调整。

两个场景共用同一卡片几何：图片、占位与边框使用约 6 屏幕像素的圆角轮廓，边框在相机缩放中
保持约 1 屏幕像素。hover / focus 只让边框变亮、横图放大至 110% / 竖图放大至 108%，并施加
幅度受限的指针透视倾斜。float 鼠标悬停在约 240ms 内平滑摆正平面倾角，提前或完全释放均从当前角度继续旋转；
键盘聚焦不触发摆正。waterfall 保留布局角度。两页的局部高亮直接作用于原有边框，复用磁吸坐标，
越靠近边缘越亮；触摸不激活鼠标效果，waterfall 超过 `5G` 后关闭透视与局部高亮，保留普通高亮和放大。
透视期间鼠标命中边界使用卡片四角的同一投影，不包含阴影扩展；倾斜回退期间同步更新，恢复平面后恢复矩形命中。
运行时通过原生画布指针事件记录指针是否仍在画布内；离开画布、浏览器窗口失焦或页面隐藏时，
立即清除悬停与磁吸并关闭场景指针命中，键盘焦点保留。只有再次收到画布内的原生指针事件才
恢复命中，Pixi 使用旧坐标派发的 document 合成移动不能触发边缘图片高亮。纹理按
屏幕尺寸选择 LOD，WebGL2 使用 mipmap，并受条目、像素和在途加载预算约束；场景切换释放旧控制器
与输入，路由卸载再释放 Canvas、ticker、事件和全部纹理引用。临时透视网格与边框网格拥有的
几何缓冲随网格一同销毁，不等待渲染器的空闲回收；共享图片纹理仍由纹理缓存统一持有与释放。
极高或极宽原图按目标卡片比例居中裁剪后解码，避免挤压。容量暂时不足时，卡片等待其他引用释放再
领取纹理，等待随卡片回收取消，不重置移动位置。网络传输失败暂停该 URL，同来源连续失败后暂停
该来源请求；浏览器恢复联网或用户恢复自动播放时统一重试，HTTP / 解码失败则不在本次运行时反复请求。

画廊和展映共用带显式 `view`、`limit`、`order` 与规范筛选的 `GET /api/images`。画廊按视口
几何向上选取首批 60 / 120 / 180，剩余内容不足约一屏时续取 60；展映按初始驻留需求加
100 张缓冲向上选取 200 / 500 / 800，续批为 100。筛选或顺序切换时取消旧请求、冻结巡航并保留旧平面，首批新结果成功后再
原子替换，避免新旧条件混屏。数据池最多保留 800 个唯一 DTO，候选不足时允许空间槽复用图片，
但不扩大 DTO、Sprite 或纹理 / 解码预算。同图副本各自持有键盘焦点：聚焦一个代理只高亮对应卡片，
float 的其他副本继续运动。指针打开详情返回画布宿主；键盘打开详情返回实际代理，代理已被回收时
不向失效元素归还焦点。鼠标重新操作画布时将真实 DOM 焦点从代理交还宿主，防止旧卡片随列表更新重新激活。
详情打开期间冻结导航原有显隐，暂停代理焦点同步；关闭后保持原导航状态，等待新的原生画布指针事件恢复命中。
卡片回收或换图不继承旧焦点。
补图成功但连续四批没有新候选时让出本轮；窗口为空且仍有后续页时保留需求分轮续扫，
接收新候选或到达末页即结束该续扫，筛选切换、停用及卸载取消待执行任务。
空窗口的末页若只有近期已见图片，则重新接纳该页有效候选；已被本地移除的图片继续屏蔽，
空末页或全部被移除的末页不会触发自动环回请求。
空池重新填入候选时开始新的消费轮次，使在途旧快照失效，并同步重置两个场景的消费记录；
即使中间空池没有单独渲染，同 ID 的新候选也可以重新参与展示。
补图失败后等待显式重试或筛选变化，场景补图信号不会触发重试循环；删除成功会隔离较早的读取，
编辑快照直接更新基础字段和筛选成员；仅缺少权威快照时对原列表批次执行一次条件重验证。float 随机池增量更新保留原候选顺序，
仅新增候选参与洗牌，避免补图重排已显示卡片。

公开列表要求显式 `view=show|gallery` 和 `limit=1..800`；省略 `order` 时使用 latest。
latest / oldest 分别按 `image_time,id` 降序 / 升序分页，保留微秒边界；random 按 UUID
尾部 48 位及 UUID 决胜排序，以 UTC 日期的 SHA-256 派生公共起点，先走起点至末尾再走头部。
同周期同筛选返回同一原始批次。客户端透传无状态 Base64URL cursor：有序游标为 31 字符，
保存 7 字节精确微秒时间与 16 字节完整 UUID；随机游标为 26 字符，保存 3 字节 UTC 天数
与完整 UUID，环形阶段由尾段和当天起点推导。筛选与遍历方向由当前请求决定，页面切换条件时
从首批开始。随机跨日返回 `409 cursor_expired`，用户重试从首批开始。
严格 schema 对未知参数或非法值返回 `400 validation_error`。

show 投影固定为 id、title、thumb_url、width、height；gallery 在其基础上提供 author、device、
brightness、theme、tags、image_time。卡片标题使用去除首尾空白后的 title，空标题使用图片身份提示。
主题返回稳定 slug 或 `null`，标签返回稳定 slug，显示名复用 facets。PG 按用途窄投影，Redis 复用同一 rich ready-cache；
随机读取在既有尾段索引上扫描并探测筛选成员，达到单次 4096 扫描预算时回源同序 PG 读取。

列表使用 `public, max-age=30, s-maxage=60`，随机页新鲜期另收口至 UTC 当日剩余秒数。
公开详情按管理员身份投影原图链接，统一使用 `private, no-cache` 与 `Vary: Cookie`，每次 HTTP 读取均重验证。
列表普通读取使用浏览器默认缓存；确认编辑优先，缺少权威公开数据的活动查询
才显式使用 `no-cache`。
列表 ETag 覆盖完整原始 JSON 和 next_cursor，详情 ETag 仅覆盖详情 DTO；权限、ready 可见性、
404 和周期错误在条件验证前处理。浏览器保存原始实体与验证器，页面另建洗牌 / 详情组合模型。
随机批次只在当前浏览轮次首次接收时洗牌，水合保留已接受的 ID 顺序；新轮次可重新洗牌缓存批次。

画廊与展映通过工具栏排序菜单选择“随机模式 / 最新优先 / 最旧优先”，保留筛选并从首批开始；画廊返回顶部按钮位于右下角。
画廊、展映及其嵌入页按用户操作更新地址栏参数：修改或清空筛选保留已有的显式 order / mode，
省略的参数继续跟随站点默认；点击排列按钮只写 order，切换展映模式只写 mode，其他参数原样保留。
内部数据源身份与 API 请求使用解析后的筛选和排序，不将这些默认值反写到页面 URL。
画廊、展映及其嵌入页共用导航工具栏；鼠标悬停或键盘可见焦点保护导航展开，弹窗归还的普通指针焦点不阻止滚动收起。
详情打开期间避让并冻结导航状态，关闭后恢复原位置和焦点规则。

画廊挂载时无条件并发请求
`gallery-facets`；该查询以同一 query key 在会话内长期复用，并由词表或图片成员变化显式失效。
Web 通过同一纯投影把 facets 建成 slug 显示映射，卡片与详情首帧共同消费：标签以 `/` 连接，
主题与标签同时存在时以 ` · ` 分隔，主题为 `null` 时不进入卡片副标题。列表先到或 facets 失败时
显示 slug，facets 成功后原位更新显示名。没有标签条件时图片列表不等待词表；有标签条件时，
先使用同一词表解析显示名与 slug，再启动图片请求。公开标签词表包含零图片词条，以区分合法
零匹配与未知标签；主题和作者候选仍按现有成员范围返回。词表读取失败显示加载错误。

长时间滚动使用数据窗口而不是无限 React Query pages：

- cursor 目录只长期保存页边界、顺序 ID 和 typed-array 紧凑布局；
- 完整 DTO 只保留视口附近最多 480 张，以及当前被详情固定的一页；
- DOM 与物化位置对象只覆盖前后缓冲区，最多 180 张卡片；
- 渲染窗口只在视口累计移动半屏或视口高度变化时重定位；三屏 overscan 在边界前仍覆盖至少
  两屏半，继续包住共享图片加载器的两屏驻留区；
- 远页回到视口时按保存的 cursor 重新获取，临时 Query 结算后立即从 cache 移除；
- 页集合或下一边界变化时从该页截断旧链，迟到响应由请求 token 丢弃；
- 远页获取失败时，重试操作固定显示在当前视口。

画廊缩略图由共享可见性观察器和解码调度器决定何时设置 `src`。真实视口、近端缓冲和
详情原图使用不同优先级；离开驻留范围会移除地址和引用。列表已知宽高用于预先计算瀑布
流位置，列数变化或图片比例更新时以可见卡片为锚保持滚动稳定。地址加载失败时只显示统一
损坏图标，不在组件内部切换备用地址或追加 cache-busting 重试。

### 详情、原图与移入回收站后的收敛

页面保留当前图片的列表基础项；详情请求提供 id、author、device、brightness、theme、tags、
image_time、description、source、object_url 与可空的 original_url。同图按 ID 组装，有效详情覆盖同名
列表元数据，已确认编辑快照优先。本地会话提示只触发
`/auth/me` 探测；服务端确认已认证后才按需加载管理信息与编辑能力。未登录、过期提示、
401 与 403 路径都不会下载管理 JS 或 CSS。详情标题固定在新标签页打开该图片的直链，
不提供运行时开关或条件分支。

公开画廊、展映及其嵌入页的详情只向有效管理员会话返回非空 `original_url`，访客为 `null`。
管理员在公开页面及后台查看图片详情时均可使用原图按钮，且只在服务端确认存在另一条合法
HTTPS 原图时显示；加载中、失败或空链接时不渲染按钮。“来源”固定在动作区左侧并始终渲染，
详情尚未完成或无来源时沿用现有不可用状态与提示；动作区不换行。
公开详情、后台图片读取和编辑快照的 `source` 与 `original_url` 均使用 `string | null`。
数据库与编辑 / 接入草稿仍以空串表示未填写来源；读取投影和回填草稿各自完成
转换，清空来源后以可空权威快照收敛保存状态。
详情独立包含 image_time 等元数据；title、thumb_url、width、height 由同图基础项提供。
只更新这些基础字段时详情仍可返回 304；详情字段变化时其内容验证器随之更新。
编辑完成会取消之前的详情查询并保留一个共享新鲜窗口内的验证意图；已打开的弹窗使用确认快照，
关闭重开且没有该快照时才执行一次条件重验证，旧请求不能被新弹窗接管。

共享图片详情弹窗的高清 frame 在未就绪且透明时继续不可命中；进入就绪态后才恢复真实
`<img>` 的原生命中，因此公开画廊、后台概览、后台图片列表和内容接入窗口中的桌面右键或
触摸系统长按始终命中当前展示的 `object_url` 标准化图片。缩略图淡出前后不会成为保存目标；
详情以外的图片预览等 `ProgressiveImage` 消费者继续沿用不可命中的共享默认值。

完整展示图加载失败时，共享 `ProgressiveImage` 显示失败提示和“重试”按钮，保留仍可用的
缩略图。重试只重新加载当前完整图，不自动定时重试，也不触发外层预览的关闭或放大。
图片 ID、完整图地址或本次重试变化时重新建立加载任务；换源和关闭取消旧任务，迟到解码
结果不能覆盖当前图。取消不显示失败提示。

公开详情统一使用 `private, no-cache` 与 `Vary: Cookie`，内容 ETag 在按身份投影原图链接后生成。
Web 按图片 ID 与认证身份隔离查询，管理员携带同源凭据、访客省略凭据；等待已有认证探针完成，
不增加认证请求。编辑和移入回收站按图片 ID 取消或失效对应详情，身份变化后不复用管理员结果。
管理员的管理信息与编辑能力继续由独立受保护读取提供。
后台读取、编辑快照及回收站使用 `/images/original/<id>`。该接口先校验 Redis 会话及
PostgreSQL 管理员账号；图片管理员与超级管理员均可访问，无有效会话返回 401。
鉴权后完成一次图片解析，再进行直连决策或受限代理；直连结果按原图 URL 与 User-Agent 家族缓存。
直连 302 与代理成功响应统一使用 `private, no-cache`，每次资源访问（含条件请求）均须先鉴权，
不继承源站公开缓存策略；GET、HEAD、取消及 URL 绑定验证器保持有效，响应带
`Vary: Cookie, User-Agent`，错误及失败回退不缓存。原图资源可读取正常图片及回收站记录，
公开列表和详情仍只展示 ready 图片；正式展示图、缩略图及其原生保存继续使用稳定公开地址。

公共详情中的移入回收站成功后，画廊窗口取消相关在途页并局部移除 ID；编辑成功后，权威
快照同步更新同图基础项、几何与筛选成员。没有快照时才通过该页 cursor 重验证，迟到响应不能覆盖已确认编辑。

公共画廊、后台概览、图片列表和内容接入窗口共用同一个图片详情弹窗。最外层
`DialogLayerPortal` 与应用根节点并列，并独占当前 `100dvh` 动态视口；移动详情 article
继承该高度并作为唯一纵向滚动 owner。首个共享页面锁固定
`#root` 并临时设置 `inert` / `aria-hidden`，嵌套弹窗只增加同一计数；最后一个锁释放时先恢复
根节点交互属性与原样式，再恢复精确页面位置和各层 opener 焦点。

触控弹窗打开期间，共享锁在 capture 阶段识别顶层弹窗内真正溢出的纵向 owner，以及显式登记的
标签横向 owner。单指越过意图阈值后按累计位移锁定主轴：纵向仍由最近可滚动 owner 原生消费，
横向则由同一个标签 viewport 显式消费，所以从 chip、空白或输入区起手都不会选到不同 owner；
到达对应边界时锁住滚动链，没有横向溢出时不认领输入框的原生光标与选择手势。纵向输入手势、
双指缩放与弹窗文本选择继续走原生路径。监听和临时 overscroll 样式只在锁计数非零时存在。
移动详情关闭按钮属于根弹窗层、安全区内命中面不小于 44px，并在
pointerup 直接提交关闭；桌面标题栏、键盘、Escape 和背景路径均可关闭。移动详情
关闭 article 的位移动画、图片 paint containment 和完整图 opacity 合成动画，公开 Gallery
卡片的全局图片优化不受影响。

发布前的移动 Chromium 与桌面 WebKit 手机尺寸验证只证明 DOM、CSS、事件、动态 resize、
滚动和焦点契约。它不具备物理 iPhone 的 Safari 浏览器栏与合成器环境，不能替代发布后的
工具栏展开 / 收起、地址栏位置、0–200ms 立即手势、横竖屏和减少动态效果真机验收。

随机图的查询、去重、`size` 尺寸选择、`proxy` / `redirect` / `json` 返回方式和 PostgreSQL 降级见
[随机图 API](./random-api.md)。

## 后台管理

### 权限

图片管理员可以管理图片、上传 / 导入、常规元数据、主题、标签、作者和检查；超级管理员额外
拥有用户、存储、配置、永久删除、词表删除、整后端迁移和缓存重建等能力。
前端先按角色过滤路由发现与导航预加载，再按能力矩阵隐藏或禁用页面内入口；图片管理员
直接访问超级管理员 URL 也不会先下载对应页面。服务端仍在每个接口独立校验，不能通过
直接请求绕过。

管理员会话保存在 Redis，但每次认证都会按用户名读取 PostgreSQL 账号并校验角色和密码
代际。数据库不可用时保留会话并返回 503；只有真值明确失配时才删除会话并返回 401。
`session_ttl_seconds` 是空闲超时：仅已认证的 `/auth/me` 在完成响应依赖读取后原子刷新当前
Redis payload 的 TTL 并续发 Cookie。普通管理请求不 touch，会话也没有定时探针；首次直达后台
或公开页已有本地提示时产生的既有 `/auth/me` 请求就是续期点，页面间切换不追加请求。

### 作者主页与导入身份

后台主题、标签、作者列表的图片数量统一统计全部关联图片，包含回收站；作者保存响应采用
同一口径。删除确认明确包含回收站，解除全部关联；移入或恢复不改变关联数量，无需失效
服务端关联计数。永久删除会失效三类后台计数。公开首页、画廊与随机 API 仍只统计 ready 图片。

作者管理仍只有一个 HTTPS 主页链接输入。Server 在作者新建或资料更新的独占变更锁与同一
PostgreSQL 事务内，从严格的 `https://weibo.com/u/<UID>` 链接派生微博身份；清空链接、改为其他
合法 HTTPS 地址或换绑 UID 时同步清空或替换身份。客户端不能提交内部 provider / ID。新建与更新
成功均返回已提交的权威作者项；同一微博 UID 已属于其他作者时返回 409，链接与身份都不发生变化。

管理作者列表额外得到只读 `derived_identity` 投影，前端仅用它给现有链接输入设置原生 `title`，
格式固定为 `平台: <provider>; UID: <id>`，直接显示 Server 返回的 provider，不维护平台中文名；
前端不自行解析 URL。保存成功后直接以响应项替换作者查询缓存，并只失效受显示名 / 链接影响的图库
facet、统计与 Ingestion 词表投影，不追加作者列表 GET，也不改变卡片布局。公共图片 API 继续只
返回作者公开链接；历史图片的作者关联不会因主页身份换绑而改写。

### 标签基础筛选与分组

首页、画廊、展映、对应嵌入页以及后台图库 / 无主题 / 回收站均支持标签任一 / 全部。
任一匹配至少一个已选标签，全部要求具有所有已选标签且允许其他标签。切换方式保留已选项、
搜索词、焦点和弹层；公开筛选弹窗移除最后一个标签后保留本次模式偏好，重置全部草稿才恢复任一；
首页与后台继续在移除最后一个标签或整体清空时恢复任一。无标签时可预选全部方式，但不生成
空 `all:` 参数或额外图片请求。单个显式 `all:` 保留编辑意图，等价查询复用分页与数据身份。

画廊、展映及嵌入页从重复 `tag` 参数恢复标签组合，每段保留组内任一 / 全部和成员；多个参数之间为或。空组不写入 URL，重新打开按非空组顺序编号；仅剩一个非空组时按普通任一 / 全部展示。非法、超限或未知标签显示筛选错误并保留 URL，
可清空全部标签参数后重选。未知标签还可“刷新标签并重试”，通过原共享词表查询重新验证
HTTP 缓存，并保留全部 URL 条件；重复点击共用在途请求，词表更新后原位恢复图片读取。
词表连接与响应体每次读取限时 30 秒，挂起请求退出后可再次刷新。刷新失败明确显示词表读取
失败，不以旧缓存的“未知标签”冒充本次已重新验证；刷新成功后仍未知则继续显示标签错误。
语法或范围错误不刷新词表。合法条件形成前不发送扩大范围的图片请求，也不生成随机链接。
首页保留本地筛选状态和唯一统计查询；后台保留现有筛选状态、五属性计数及视图 / 分页职责。
页面更新和跳转由路由 API 写入统一的可读查询串，逗号和冒号保持可读；复制、跳转与请求条件一致。

`/api/images`、`/api/admin/images`、`/api/gallery-stats` 共用分组解析：每个 `tag` 为任一或全部的一组，
参数之间为或，重复条件规范化为同一执行表达式。首页和后台选择器保留简单任一 / 全部界面。标签值在对象转换之前完整提取，不能丢掉重复
参数或预先压平。空值、非法格式返回 400，合法语法中的未知标签整体返回 404；存在但零匹配时
列表为空、matching 为 0。解码后的全部标签值合计最多 1024 字符，最多 9 组，每词最多 64 字符。
标签先规范化并去掉同一子句内的重复词及完全相同的子句，再按所有子句的词项合计检查 32 项额度；
不同且子句中共享的标签仍分别占用额度，不进行分支吸收等布尔化简。原始输入长度与组数独立约束。
取消标签可能使原本相同的两个组变为不同子句，暂时超过额度；保留取消结果并允许继续删减，
此时提示超额、停止动态统计并禁止应用，恢复合法后继续。超额的新增选择仍被拒绝。
随机混合语法和预算见[随机图 API](random-api.md)。
页面使用 slug 保存和分享条件，显示名解析后的规范串也须满足基础长度预算；超限显示可恢复的
筛选错误并保留原 URL，模式切换被拒绝时保持原条件和选中态。

首页、公开筛选弹窗及页面路由共用主题 / 作者校验，每个字段最多 32 项，规范串不超过 1024 字符。
超限选择不会写入草稿；同一字段混用包含和排除、无效 slug 或超限 URL 均显示可恢复错误，
不丢弃条件或生成放宽后的查询与分享链接。弹窗保留原始错误条件，取消不改 URL；可以逐字段清除，
其他条件保持原样，所有错误解除后才恢复查询和应用。

列表、统计及随机共用标签表达式和执行签名。matching 使用完整条件；设备、明暗、主题和作者
候选统计保留标签条件。统计接口额外接收 `tag_scope`，为重复 `tag` 参数中从 1 开始的且组序号；
未提供时标签候选统计移除整个标签维度，提供时只保留该组标签与其他属性条件，对全部候选计算交集。
序号越界、非整数或指向或组返回 400。首页的且模式自动选择唯一组，弹窗指定当前非空且组；
空组不限制候选数量。统计保留输入组边界，有标签条件时返回 `tag_groups: [{ tag, image_count }]`，
顺序与重复 `tag` 参数一致，`tag` 回显对应条件。各组数量按非标签条件单独计算，matching 对组间或的结果去重。
图片与标签变更继续通过现有 revision 和失效路径刷新派生结果。

### 图片列表与分页

后台图片页的主题、标签和作者筛选使用 `FacetSelector`，公开图库使用上文的目录式弹窗。后台收起时显示
带当前筛选方式与数量摘要的筛选按钮；展开时同一位置直接换为搜索框和显式收起动作，搜索框不
进入按钮；直接触摸、鼠标或键盘激活会在该次事件返回前同步挂载并聚焦搜索框，让 iOS 软件键盘
由第一次触摸直接进入输入态。字段标题始终显式关联当前显示的按钮或搜索框。锚定 Portal 弹层以受搜索框控制的非模态
区域承载待选项、已选项、分隔区与方式切换：主题 / 作者使用包含 / 排除，标签使用任一 / 全部，
保持既有顺序、滚动和向上 / 向下展开规则；
页面根 Portal 以当前实际 fixed 绘制原点统一锚点、可见边界与弹层样式坐标，软键盘平移视觉
视口时仍保留与内联搜索框的间隔。页面内搜索框与 Portal 内按钮按一个连续键盘顺序衔接，并以读屏状态报告搜索
结果。关闭或移动筛选面板隐藏时清空搜索词，但 URL、词条顺序、显示名、未知值与
筛选结果语义不变。

Facet 内联搜索框显式隐藏浏览器为 `type="search"` 提供的原生搜索词清除按钮；筛选项只能通过
候选与已选操作修改。后台图片页另有针对五项已提交筛选的整体清空按钮；
五项均为空时仅禁用该按钮，筛选入口仍可使用。

后台图片筛选在桌面单行按设备、亮度、主题、标签、作者排列；容器进入双行时改为第一行设备、
亮度、作者，第二行主题、标签、操作。组件在同一个 `947px` 容器边界实际切换 DOM 分组，使视觉、
键盘与读屏顺序一致；移动端继续采用设备、亮度、主题、标签、作者顺序。设备和亮度以 `120px`、
其余三项以 `150px` 同时作为弹性基准与下限，行内剩余宽度按项等量增加，因此前两项可以稳定
短于三类 Facet，而不会挤压其六字符筛选摘要。

后台图片列表提供图库、无主题和回收站三个视图，以及设备、明暗、主题、标签和作者
筛选。当前页可以普通选择、全选或用 Shift 建立连续区间；翻页、换视图、换筛选、换排序或项目
离开列表时清理失效选择，不跨页保留。

图片列表固定使用紧凑卡片布局。分类摘要先显示设备 / 明暗，再追加非空主题；无主题不显示占位文字。
工具栏双分区排序控件左侧切换“图片 / 入库”，右侧切换“最新 / 最旧”，两侧独立单击，
中间以竖线分隔，不展开菜单；两侧各保留一个随状态左右移动的滑块，文字显示在滑块另一侧，
系统减少动态效果时直接切换位置。图片对应 `image_time`，入库对应首次正式入库的 `created_at`。
两项选择自动保存为当前管理员的账号偏好，桌面与手机共用，重新进入图片页时恢复；未保存时
使用图片时间最新优先。当前页面内跨筛选、视图和翻页保留，其他窗口同步偏好不重排正在操作的列表。
切换任一侧保留筛选、回到第一页、滚动到顶部，并清空选择与瞬时反馈；忙碌和模态期间禁用。
控件高 36px，桌面宽 118px、移动端宽 106px。移动端保留全选与批量操作的位置，
窄屏第一行固定为 36px，批量操作继续位于第二行。

“清空”以一次筛选状态替换同时移除这五项，不循环触发单项变化。它不改变图库 / 无主题 /
回收站视图，并沿用普通筛选变化的收敛：清除当前选择与瞬时反馈、返回第一页并把列表滚动到
顶部；无主题视图中暂时不参与查询的主题值也会删除。最终只建立一次无额外筛选的查询键，并
继续服从 90 秒查询缓存。后台忙碌时筛选和清空都不可用；移动面板中的清空只关闭内部下拉或
Facet，不改变外层面板开合。

移动端宽度与高度同时不足时，筛选面板继续使用有界纵向滚动，但不在面板内部重复提供“收起筛选”
按钮；用户仍通过始终可见的顶部筛选主段收起面板，滚动区域直接从筛选项开始。

图片列表使用服务端权威数字页。后台查询是严格对象，只接受共同筛选、正安全整数 `page`
与 `limit`，以及 `sort_by=image_time|created_at`、`order=latest|oldest`；省略排序参数时采用
`image_time`、`latest`。`cursor`、`offset` 或未知字段均返回 `400 validation_error`。服务端集中计算
`PageWindow { page, limit, start, endExclusive }`，响应只包含 `{ items, total }`，任意有效
目标页直接读取而不建立前序边界。合法页的 `start >= total` 时返回
`200 { items: [], total }` 并跳过目标窗口读取，不在服务端静默改查最后一页。

ready 与无主题页先解析一次规范化筛选计划。按图片时间排序时，沿“索引句柄 → 页码位置适配器
→ Redis 有序窗口 → 当前页水合”读取，latest / oldest 分别反向 / 正向读取索引；窗口最多读取
`limit` 个成员，total 复用读取前索引校验同时取得的 cardinality，不再单独计数；空结果中的
0 也是有效计数。读取后仍再次校验同一索引、revision 和派生实例，保留完整性与失败处理。
coordinator 正在重建、revision 改变或派生索引暂不可读时，允许使用同一个筛选计划回源
PostgreSQL；Redis transport、连接或命令失败则标记运行时不可用并返回稳定
`503 redis_unavailable`，不会伪装成成功回源页。筛选计划读取或补写主题、标签和作者的
Redis JSON 词表也使用同一 required-read 失败合同。入库时间排序与回收站直接走 PostgreSQL
OFFSET；数据库按所选时间字段与完整 UUID 同向排序后分页，不在 Web 或单页结果上重新排序。

PostgreSQL 回源在同一连接的 `REPEATABLE READ READ ONLY` 事务中依次读取 total、判断越界，
再取得当前页 metadata 与随窗口投影的 tags；事务提交后才做 URL 和 DTO 格式化。浏览器端
`useImageAdminPageNavigation` 是唯一查询 owner，查询键包含带排序字段及方向的规范化 scope、page 和 page size，
目标缓存 90 秒内可零网络复用。同一 scope 跳页时继续使用最近成功且最新的 total 快照展示
总项数与总页数，但不把上一页 items 伪装成目标页内容；已有成功快照时，目标页尚未返回或
请求失败都不会把未知数据解释成 `0`，也不会用目标页码反推总页数。请求进行中时，副标题
保留稳定的页码、总页数与总项数，只显示“加载中”，不展示尚未确定的当前页项数；成功后
才显示“本页 x 项”。目标页失败且没有缓存数据时也不把缺失 items 显示为 0，而由错误区域
提供重试；已有缓存的后台刷新失败后仍可显示该页实际项数。scope 改变时当次渲染立即使用
第 1 页并清除旧 scope 的 total；成功结果使总页数收缩时只直接夹紧一次，目标页失败则保留
该页与错误并在原页重试。主题、标签、作者和上传队列等普通分页页面继续使用各自的本地
分页，不接入图片列表协议。

### 编辑、迁移与删除

公开详情、后台详情、概览和图片列表共用同一详情与属性编辑能力。
共享响应按真实消费者分成独立形状：公开列表只返回画廊卡片与详情首帧所需字段及稳定主题 / 标签
slug，公开详情只补充描述、来源和展示图地址；后台图片列表返回卡片操作所需的完整状态、对象、
大小和时间字段，概览最近图片使用不含删除状态与编辑字段的紧凑详情，编辑快照只返回恢复草稿
与画廊权威回写所需字段。三个后台形状互不继承可选字段，也不会用缺列补零来伪装同一投影。
公开画廊卡片与登录后按需读取的编辑快照都不返回副标题或显示名；Web 使用会话级 facets 从
slug 生成本地展示值。登录用户保存主题或标签后，画廊先用权威快照即时回写稳定 slug，相关
facets 同时失效并重取显示名，再由命中页 cursor 回读核对成员和分页边界；不从副标题反向解析，
也不让列表服务端为每个 cursor 页重复读取和投影同一份词表。
展映的候选池独立于分页位置：保存确认快照暂时不可用时，恢复读取按图片 ID 获取编辑快照，
再按当前筛选判断是否保留。只有成功快照确认图片缺失或不再匹配时才移除；读取失败保留
已有候选，新增图片或排序位置改变不会使仍有效的图片被持续排除。
概览紧凑详情在读取最近图片的同一 PostgreSQL 语句中解析存储显示名，只返回详情直接消费的
`storage_label`；`storage_slug` 仅在服务端定位对象。因此概览打开后台详情时首帧
直接使用权威显示名，也不会为了已随概览返回的 MD5、时间与存储标签再请求 `admin-info`；
后台图片列表仍以自身已缓存的存储选项解析显示名，公开详情按认证状态保留独立管理信息查询。
编辑器始终建立一个 `items` 会话；单图只是其中只有一个成员。成员数量只决定标题、
副标题、文案、分页、
批量默认值和移出按钮，编辑器 shell、列表、卡片、动作和公共属性实现均使用数量中性命名；
快照、草稿、保存、移入回收站、迁移、权威回读与卡片结果使用同一实现。
移动端的批量默认属性使用共享折叠面板。“应用到全部”会同步重算草稿或任务卡片，折叠开关会
同步隐藏、设为 inert 并重定位面板内容；两者都使用共享 `DirectActivationButton`。触控 / 笔在
移动量未超过统一 5px 阈值的 `pointerup` 直接提交各自动作，鼠标、键盘与辅助技术继续走原生
click；迟到且可能在重绘后重新命中的同手势兼容事件由已有守卫消费。下一次物理 `pointerdown`
先释放旧手势守卫，再由新目标建立自己的激活事务，因此相邻两次真实触控不会互相吞掉，也不依赖
WebKit 一定把延迟 click 派发给原触点元素。共享按钮的触控 / 笔目标聚焦统一延后到手势已经按
原始布局通过 `pointerup` 校验之后，因此选择菜单、“应用到全部”等默认按钮仍会正常接管焦点并
收起软键盘，但不会让视觉视口在同一次物理按压尚未提交时复位并改变命中目标。目标聚焦触发的
编辑器失焦结算在动作读取前同步提交，动作使用该次重渲染后的最新回调，因而“应用到全部”不会
漏掉刚由失焦接收的标签。需要继续编辑的复合标签候选与移除控件保持原输入焦点；折叠触控同样
保留输入焦点直至提交收起，再释放被隐藏的编辑焦点，键盘、辅助技术及程序化 `detail=0` 激活则
继续把焦点留在披露按钮上。三种焦点策略集中在共享按钮，不由工作流页面补定时器或坐标特判。
折叠面板自己的捕获阶段 `touchstart` 只负责外部触控关闭，不建立页面入口特判、额外延时器或
第二套展开状态。
“应用到全部”与“导入图片”共用分体按钮的外观、悬停、键盘导航和直接触控激活。
批量编辑的四种清空动作在确认时冻结本次活动图片 ID，只更新草稿中对应字段，
继续由同一个保存、复原和权威回读流程处理。空目标不能确认，确认取消不修改草稿。
默认属性面板通过稳定交互归属标记把 Portal 菜单与确认窗口纳入同一表面，焦点或触摸转入
子层不收起面板。菜单优先消费 Escape，确认窗口只处理最上层对话框的键盘事件，
移动面板在没有子层时消费下一次 Escape 并归焦折叠开关；显式收起仍广播子菜单关闭。
确认表单阻止 submit 沿 React Portal 冒泡到编辑器保存表单。子窗口关闭时优先归焦原箭头，
若视口切换后该控件已隐藏，则归焦仍可用的面板开关。

编辑读取、保存和存储迁移分别使用数量中性的 `/api/admin/images/snapshot`、
`/api/admin/images/update` 与 `/api/admin/images/migrate-storage`；三者都接收 1–200 张图片，
单张操作就是数组中只有一个成员。编辑窗口只提交真实变化字段，服务端规范化并稳定排序整批
图片 ID 锁后，以固定低并发逐图处理并按输入顺序返回结果。每张图片的 metadata、词表创建和
完整标签替换在一个 PostgreSQL 事务内提交；一张失败只回滚该张，实际变化只
推进一次 `ready_image_revision` 并交接一次投影，纯 no-op 仍返回 `updated` 但不推进 revision。
设备、亮度或主题变化的持久化范围是 PostgreSQL 与必要投影，正式对象位置和 `thumbnail_size`
保持不变；编辑路径中的存储读取仅用于显式自动亮度检测所需的现有缩略图。

编辑明确采用 last-write-wins，不存在逐图编辑 revision、预期版本、冲突响应或三方合并；
陈旧窗口最后提交时可以覆盖较新结果。同一图片的在途请求由锁串行，锁不证明窗口最初读取的
快照仍为最新。保存先深度冻结本轮 ID 和字段意图，单次写请求从连接到完整 JSON 响应体
读取限时 30 秒；超时只终止客户端等待，不能证明服务端没有执行。响应丢失、超时或部分失败后，
前端只沿同一请求锁边界读取 PostgreSQL 权威快照收敛，
不会自动重放 mutation。PostgreSQL 已提交即视为成功；Redis 投影、词表或计数缓存修复失败
只记录并失效或安排重建，不能把已提交结果改成可安全重试的普通失败。
Redis 冷启动、上游 502 / 503 / 504 或短暂网络错误会触发有限的快照回读重试，不会重放
写请求。卡片直接显示绿色“保存成功”、红色“保存失败”或黄色“待确认”；待确认状态
保留草稿，再次点击只重试权威确认。检查页随后恢复为 Redis 正常并不能反推较早请求未
经历短暂故障，保存结果仍以对应批次的 PostgreSQL 快照为准。写响应与快照均缺失时先按真实
尝试字段保守刷新；此时服务端可能仍在写入，后续人工确认首次取得权威快照后，再向父页面
交接当前值，更新列表、详情及相关词表。无写回执时，`auto` 等指令不能从当前值证明执行成功，
仍保留未确认草稿，但不阻止父页面采用权威数据。已收到写响应的保存不在人工确认时重复失效。
有写回执的保存只把服务端确认已更新成员及其真实变化字段交给查询失效所有者；无回执时按
实际尝试字段保守刷新。保存状态和草稿按权威快照立即收敛，不等待派生查询完成；父页面同步
接收快照并继续后台刷新，其请求生命周期与失败反馈仍归原查询所有者，不能因列表或相邻
信息读取挂起而锁住已保存的编辑窗口。公开
Gallery 先用同一次权威快照原位替换命中卡片，再后台重读唯一命中页；该页不会在等待期间
退化为占位符，未变化卡片继续复用原对象和图片 DOM。后台结果确认筛选成员、缩略图比例、
游标或顺序改变时，数据窗口才原子调整对应成员、几何与锚点。列表、详情、facet、stats、
overview 和词表分别只在自身字段受影响时刷新；公开编辑与后台编辑共用同一 mutation、
快照和编辑会话能力，不建立第二个公开查询所有者。
快照 POST 只读取权威图片，不记录为管理员写操作；仍要求有效会话和 CSRF。
图片更新省略 `theme` 表示不修改，显式 `theme: null` 表示清空；接入创建的缺省主题为 null。
单图编辑清空主题输入后保存即发送 null。默认属性栏未填写仍不应用，不隐式清空已有图片。
“未设置”统计入口使用 `null` 查询选择器，与真实主题词条分离。

分类变化由 `images/image-update-item.ts` 直接提交 metadata。显式分类及自动设备只从事务内
锁定行计算，分类请求仍要求 ready；自动亮度才在事务外读缩略图，并在提交前复核准备快照。
自动亮度直接 GET，只有驱动明确缺图时保留旧亮度；后端解析、权限、网络、取消和解码错误仍报告。
请求级图片更新锁、词表关联锁、mutation fence、图片 revision 和提交后 cache handoff 保留，
单图对象锁只用于需要读取缩略图的组内成员。
主题删除由 `themes/mutations.ts` 在词表排他锁之后进入同一图片缓存 fence，单事务集合更新
全部 ready / deleted 关联为 `NULL` 并删除词条；有 ready 变化时只推进一次 revision，最多 500
张精确交接，超出时请求重建。提交前观察到的失败或取消整体回滚，提交响应丢失不代表回滚；
词表与计数从数据库同步，已提交后的图片缓存故障继续由协调器恢复。
对象传输由单图、批量与整后端迁移通过 `images/storage-location/` 的图片位置能力发起，
复用 storage 域的对象验证、持久清理与共享传输准入。
管理端以同一个保序列表编排器报告逐项迁移、跳过与失败，单图只是列表中只有
一个成员。迁移响应同时返回服务端解析的目标显示名；后台与公开登录详情都优先复用或按需
执行同轮管理信息回读，并在处理编辑快照结果前保留其成功值。相邻回读失败时采用迁移响应值；
管理信息回读成功后，其显示名始终优先于同轮其他响应。
整后端迁移的流式分页也直接调用同一单图原语，精确语义见[存储](./storage.md)。

移入回收站、恢复和永久删除分别只使用 `/api/admin/images/trash`、`restore` 与 `purge`，
前两者接收显式 `1..200` 个唯一 `ids` 并按请求顺序返回逐项结果；trash 响应计数为
`trashed`，逐项状态为 `trashed` 或 `ignored`；单图只是数组中只有一个
成员。`purge` 的正文只能是 `{ scope: "selected", ids: [...] }` 或
`{ scope: "all" }`，空数组、缺省字段和数量哨兵都不能表示全部。所有永久删除都需要
`image.trash.purge`。移入回收站和恢复与
编辑快照共用稳定排序的单图锁；写响应未知时先等待同一锁边界读取权威快照，再刷新页面
查询，不重放 mutation。编辑窗口内的 trash 同样提交当前活动的 `1..N` 个成员，并只把响应
中的逐项 `trashed` 作为直接成功依据，不从聚合计数推断成员结果；传输失败只让结果保持
未知，随后以权威编辑快照确认。编辑器就近的同一领域单元依次拥有 mutation、回读、会话成员
修剪、公开窗口成员交接和查询失效。部分成功时只移除已确认移入回收站的成员，仍可编辑或
结果未知的成员留在原会话等待重试或刷新。

图片编辑窗口的单张与批量删除共用图标按钮内的两次点击确认，批量提示包含当前活动图片数量。
第一次点击进入确认状态，失焦或点击按钮外取消确认；第二次点击提交，处理中禁用按钮。
最终确认使用 `delete-bin-2-line`，执行中使用 `delete-bin-5-line` 并显示删除中的提示。
全部删除成功后关闭编辑窗口，未全部成功时在编辑窗口内保留错误提示和待处理成员。

图片卡片的单图移入回收站使用同一个图标按钮内的两次点击确认；图库 / 无主题的批量入口同样在
文字按钮内按“批量删除”→“确认删除”两次点击，第一次点击冻结精确 IDs。两者失焦或点击按钮外
都会取消确认。提交后两者都禁用并使用 `delete-bin-5-line`；单图按钮保持“删除中”，批量按钮
显示“正在删除”。移入回收站与恢复取得服务端已知结果后，先满足最短进行态并在卡片仍位于当前
标签页时呈现结果，再刷新权威列表成员；刷新失败会把同一反馈改为错误并保留重新加载提示。
全部成功时反馈只显示实际移入或恢复数量；只有服务端返回未处理项时才追加对应数量，不展示
“0 张未处理”。
图片列表 mutation 使用专门的失效入口，把当前后台列表作为必须确认的刷新，其余公开列表、详情、
统计、词表和概览投影保持尽力失效；不会在通用失效循环中按调用方布尔参数特判某个 query key。
未知写结果仍先沿单图锁边界回读和刷新，不把卡片是否消失反推为成功。
单图永久删除、删除已选图片和清空回收站的入口使用 `delete-bin-6-line`，统一使用范围确认弹窗；
弹窗中的危险按钮先显示“永久删除”并使用 `delete-bin-line`，第一次点击后变为使用 `delete-bin-2-line` 的“确认删除”，
第二次点击才提交。永久删除结果在列表刷新收口后再交给页面反馈并关闭弹窗，不会在页面仍被
弹窗设为 inert 时于背后开始倒计时。永久删除请求结果未知时，确认弹窗保持打开并在自身错误区
持续展示对账结果，禁用再次确认以阻止盲目重放；用户只能关闭弹窗并按提示重新加载，不会在
不可交互的页面后方启动短时反馈。
三个永久删除入口只对具有 `image.trash.purge` 权限的超级管理员可见，服务端仍独立强制该权限。
提交后弹窗锁定，以 `delete-bin-5-line` 显示“正在删除”，并在正常情况下等待确认范围完全删除，
再关闭并只刷新一次列表。连接中断、有限
等待结束或任务异常不撤销持久删除意图；此时刷新后仍存在的 `purge_pending` 卡片显示“待彻底删除”，
禁用选择、恢复和重复删除。页面不建立轮询，失败原因与重试只在检查页显示。

桌面编辑页脚左侧放置迁移存储与删除，右侧放置取消与保存；存在多页时分页放在中间。
移动端分页独占动作行上方一行，资源动作在左、取消与保存在右；只有一页时不渲染分页行。
单成员内容保持垂直居中，窄屏仍保留不小于 44px 的触控目标。

回收站生命周期为：

1. 移入回收站只把图片标为 `deleted` 并从 ready 投影和全部公开发现入口移除，对象与
   `object_url`、`thumb_url` 留在原位；已知正式媒体直链继续使用 immutable 缓存并可读取。
2. 恢复把可恢复行写回 ready 投影，不搬对象，也不改变正式媒体 URL。
3. 彻底删除请求在一个事务中为精确集合中的每张图片创建独立 `trash.purge`，随后等待同一
   `1..N` 集合。Worker 在单图锁内核对任务 token 与图片状态，确认原图、缩略图均不存在后，
   按图片 ID、deleted 状态和对象位置条件删除 metadata。每张图片独立失败、退避与重试。
   调度取消可以退出锁与共享清理许可的等待；driver 调用开始后，当前项继续完成确认与数据库收尾。
4. `selected`、`all` 与移入回收站、恢复共享短时成员锁；`all` 只解析事务快照中的现有图片，
   后来进入回收站的图片不属于本次确认范围。`target_id` 保存单图目标，确定性幂等键防重，
   已有任务只计为 `already_queued`，不会重置失败或重试预算。恢复通过不存在对应 purge 任务判定，
   metadata 不保存任务字段，后台 `purge_pending` 由任务存在性投影。

移入回收站不是访问撤销：既有直链仍可访问。彻底删除会删除源对象，使后续源站请求无法
回源。

### 检查、反馈与外观

后台概览沿用 `queryKeys.overview` 这一个查询 owner，在同一服务端请求中并行读取 PostgreSQL
统计和 Redis 当前核心图片投影占用。Redis 测量只遍历固定核心键、准确使用
`MEMORY USAGE ... SAMPLES 0`，不扫描键空间；并发概览请求单飞合并。卡片可见副标题只显示
“占用大小 · 同步状态”；当前测量、最近完整重建回退及其测量时间保留在 hover 详情中，完全
未知时以“—”占位。活动重建的状态轮询不重复测量，完成后的既有概览刷新只测量一次。

检查页默认用一次轻量请求独立展示 PostgreSQL、Redis 和图片投影状态，同时在后台自动执行
一次有界 Redis 占用检测；轻量结果不等待检测，完整检测结果原地填充核心投影与派生缓存双卡。
每次轻量请求在同一 SQL 中扫描一次 metadata，同时聚合全部与 ready 数量，并读取当前权威
revision 和失败任务数；Redis 的 server / memory 信息通过一次多 section INFO 取得。
完整重建期间仍由现有查询所有者按秒轮询，统计不跨请求缓存，数据库与 Redis 故障独立呈现。
核心卡仍以“图片成员”展示当前轻量状态中的投影图片数，不把同一图片在 rich item、全局索引
和 ID 末位索引中的多个 Redis 成员相加；深检只补充该卡的键数与内存。派生卡继续展示深检得到的
键数、结果成员数量与内存。
自动检测进行中禁用 Redis 和“全部”入口，手动 Redis 检查继续复用同一查询，不产生并发扫描。
数据库、Redis、存储和“全部”按钮触发各自深度检查，“全部”包含回收站一致性结果。各资源
错误独立收口，一个失败不会抹掉其他结果。图片投影
区域的角色公共部分呈现当前状态、PostgreSQL / Redis revision 指纹、最近错误、刷新和准确
占用；手动重建、存储维护和整后端迁移在服务端确认超级管理员权限后才加载维护能力模块。
检查页只保留一个“存储维护”入口，弹窗同时使用当前只读存储与回收站检查结果预览缺图、
可修复缩略图、孤儿对象和持久彻底删除任务，
但必须由超级管理员再次确认。执行端在独占存储位置锁内重新读取 PostgreSQL 和 `full`、
`thumbs` 两个完整命名空间；预览同时包含缺失缩略图与数据库标记为尚未最终采用的缩略图，并按物理命名空间
去重受阻情况，不把不完整组或不可读逻辑后端的相关项算作
可执行维修 / 删除。Redis 中仍活动的 canonical 继续保护正式候选。不完整列举不会生成
修复或删除候选。维修直接写回并校验当前 local / S3 对象，
不创建后台缩略图任务；孤儿删除进入固定单调用的 provider 中性 1…N 契约，并逐项返回
`removed`、`missing`、`failed` 或 `unknown`。请求中止后不再启动后续 driver 调用；直接被中断的
调用保持可重试，不把未确认对象计为成功。数据库已记录有效缩略图时保留生成前对象探测；
记录为未采用时直接校验原图并生成，复用独占锁内的位置与 driver，再检查确定缩略图对象。存储对象处理完成后，同一
入口按执行时真值修复异常彻底删除引用，并重试全部仍有成员的耗尽任务；它不会把普通回收站
图片自动加入彻底删除，也不会强行接管仍标记为运行的停滞任务。维修与删除按主要资源分别
调度；维修替换未采用的缩略图时同样取得共享清理许可。已开始的短调用改由维护锁信号完成
确认，调用方取消只停止后续调度；执行端等待两个资源池全部收口后才释放独占锁，因此旧预览和
断开的响应都不会被当作写入真相。
本地对象列举同时保存本次有界目录事实；修剪按原顺序自底向上执行非递归 rmdir，未变化目录
不重读所有文件。维修与删除涉及的目录及祖先重新列举，根目录其余路径继续扫描；原本空目录、
深层残留及维修新建目录均参与。原有 100,000 项总修剪预算、根与命名空间保护、软链接和取消
边界不变；目录事实达到捕获上限时丢弃该快照，修剪按当前文件树继续原有有界遍历。

后台查询和 mutation 只由所属页面或共享 Hook 拥有。路由返回、Strict Mode、窗口聚焦、
弹窗开关和写操作结束都不能为同一资源制造第二个查询所有者；写操作只做一次必要失效。

后台外观可选亮色、暗色或自动，并以 PostgreSQL 偏好为真相源。站点配置或后台认证初始
读取完成前使用固定启动暗色；初始读取失败也保留该画布及满足普通文字 4.5:1 的反馈色，
认证完成后才在后台内容首帧前应用偏好。图片页冷入口的筛选控件、非选中子标签和次级导入
按钮直接消费后台语义表面；选中标签与主上传按钮才使用主操作色，不依赖迟到页面样式
把白色控件覆盖为暗色。公开页面及其中的管理弹窗始终使用公开暗色上下文。后台偏好复用
认证首帧或最近五分钟内的查询快照；认证首帧同时携带同一偏好 GET 表示的 ETag，更久后
回到窗口或网络恢复时才显式携带它条件重验证，未变化的 PostgreSQL 投影返回 304。
偏好写入队列归属于当前账号的本次挂载生命周期；卸载时取消在途请求并终止尚未发送的写入。
迟到响应不更新偏好或认证缓存，未确认选择仍留在原账号本地 pending，下次登录后再与服务端
对账和同步。取消客户端请求不代表撤销服务端已经完成的写入。

## 配置、缓存与 Worker 的交接

应用设置写 `data/config.json`，存储后端与凭据写 PostgreSQL。完整配置编辑器只管理当前
实例运行策略。配置包携带来源版本提示、可移植运行配置和自定义存储注册项，导入时按当前
默认配置和存储能力逐项识别；内容不包含数据库业务数据、Redis、图片对象或部署连接。配置项与修改方式见
[配置说明](../CONFIG.md)，模块所有权见[项目结构](./project-structure.md#packagesserver)。

配置包导入在单一 FIFO 写租约内先完成每个 S3 后端的连接与上传校验能力探测；全部通过后，
在数据库事务中登记后端及探测结果，并原子持久化候选 `config.json`。此时普通请求和运行配置
listener 仍只观察旧内存快照；PostgreSQL 正常提交或 xid8 确认已提交后才发布候选一次。确认
回滚时只原子恢复旧文件，结果 unknown 时保留并发布候选后返回明确 503，交由检查页和管理员
核对存储后端注册表。listener 的同步异常逐个隔离记录，不改变已经稳定的文件或数据库结果。

配置文件和 PostgreSQL 分别持久化。进程若在文件写入与数据库提交之间崩溃，可能出现文件
已更新而数据库回滚的情况；恢复时需核对文件和后端注册表，人工恢复导入前文件或重新导入。

图片写事务只提交 PostgreSQL 真相并推进投影 revision；精确 Redis 同步或全量重建发生在
提交后，失败不倒退业务结果。`move.cleanup`、`trash.purge` 与 `cache.rebuild` 的领取、
租约、重试和停机语义，以及 Redis Ingestion worker 的单实例恢复边界，由
[架构总览](./architecture.md#后台-worker)统一说明，流程页面不复制任务状态机。

## HTTP 缓存与按需加载

- hash 静态资源、稳定的 `/images/full/*` 与可证明存在的 `/images/thumbs/*` 使用 immutable；非 hash
  品牌资源使用短浏览器缓存。动态公共 JSON 立即重验证，随机接口与管理写请求不缓存。
- 公共与管理 DTO 只包含一个缩略图地址。配置公开 URL 的 S3 直接指向最终对象；local 与
  无公开 URL 的 S3 使用应用当前资源出口。ready 与 deleted 管理项复用同一稳定公开媒体
  URL；回收站状态只控制发现面，不增加后台 `raw` / `thumb` 字节入口。
- 应用缩略图读取不做存在性探测、repair receipt 查询、同步补建或原图降级。正式对象缺失
  返回 404，其他存储错误保持真实状态；修复必须由检查页“存储维护”显式执行。
- Home、Show 与 Gallery 的 `React.lazy` 路由和导航意图分别共用各自唯一模块 Promise。首次位于
  Home 时，主导航和次级入口的细指针 hover 或键盘 focus 只预取实际目标所需的 JS / CSS 静态闭包；
  Show 与 Gallery 的主导航入口以相同方式预取目标闭包。
  同一路由的多个入口和重复意图不会创建第二次请求，管理入口不预载；触摸、直接点击和
  地址栏导航仍走普通导航路径。预取不会挂载目标页面，因此不发送 API、facet、统计或图片
  请求。预取失败后，后续导航使用新文档取得新的原生模块映射，不复用当前文档已缓存的
  失败动态导入。
- 公开首页、展映和画廊不加载后台壳。后台路由按页面拆包；上传、详情、管理信息、编辑器和存储
  迁移只在权限确认或明确 hover、focus、pointerdown、click 意图后加载。预加载只取得
  JS、CSS 与静态依赖，不挂载组件或发起页面查询。图片管理页的“导入图片”组合按钮是
  一个统一意图边界，会同时取得内容接入工作流和来源输入两个按需块；独立上传按钮不扩大到
  来源输入块。
- 页面专属 CSS 跟随同一动态模块；共享语义颜色属于公开域或后台域基础块。内容接入与编辑器
  共用的图片工作流样式由两种能力各自携带，不依赖访问顺序。

完整缓存头、CSP、压缩、条件请求和 Range 约束见[安全](./security.md)及相关 API 文档；
反向代理不重复实现应用缓存，见[生产部署](../DEPLOY.md#反向代理与-https)。
