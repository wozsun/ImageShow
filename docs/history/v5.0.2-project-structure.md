## 工作区与依赖方向

5.0.2 使用 npm workspaces 管理三个包：

```text
packages/server ──► packages/shared
packages/web ─────► packages/shared
```

- `packages/server` 是 HTTP、PostgreSQL、Redis、导入、图片处理、存储、随机池和后台任务的
  唯一业务执行者。
- `packages/web` 是公共画廊与管理后台，不直接访问数据库、Redis 或存储凭据。
- `packages/shared` 只提供配置默认值、稳定类型、输入常量与浏览器 DTO；它不依赖另两个包。
- Server 与 Web 互不导入；Web 产物由 Server 镜像提供。

## 根目录、构建与本地测试

```text
ImageShow/
├─ packages/
│  ├─ server/
│  ├─ shared/
│  └─ web/
├─ scripts/
│  ├─ build/
│  └─ runtime/
├─ docs/guide/
├─ tests/                 # Git 忽略，仅用于本地门禁
├─ Dockerfile
├─ compose.yaml
└─ package.json
```

- 根 `package.json` 编排 workspace 类型检查、构建、Knip 与 `verify:*` 门禁。
- `scripts/build/` 生成图标、构建三个 workspace、检查 Web 产物图，并把 SPA、
  `schema.sql` 与 `schema-additions.sql` 装配进 Server 产物。
- `scripts/runtime/` 只保存容器入口和运维命令包装。
- `tests/`、fixture 与 benchmark 均被 Git 忽略，不进入 Docker build context、生产镜像或
  GitHub Actions；最终门禁从外部启动与生产镜像相同的入口。
- `schema.sql` 是 5.0.2 干净安装的唯一完整基线；`schema-additions.sql` 是纯注释占位，
  通用加载、事务与 readiness 顺序仍存在。

5.0.2 冻结基线的源码图包含 543 个模块、0 个循环和 83 个运行时配置键。生产 Web 构建中
上传工作流入口为 142.15 kB（gzip 39.16 kB）；这些数字用于判断 5.1.0 是否改变依赖闭包，
不是长期体积预算。

## Server 顶层结构

5.0.2 的服务端依赖由路由流向领域，再流向基础设施：

```text
index / routes
      │
      ▼
images / storage / random / jobs / checks / vocab / users
      │
      ▼
core / config
```

- `src/http-app.ts` 只创建 Hono 应用和路由，不启动服务或 Worker。
- `src/index.ts` 是主进程装配入口，依序初始化配置、PostgreSQL、schema、管理员、Redis、
  HTTP、导入 Worker、清理 Worker 与后台任务 Worker，并拥有优雅退出顺序。
- `src/admin-password-cli.ts` 和 `src/healthcheck-cli.ts` 是无 HTTP 启动副作用的独立入口。
- `routes/` 是 22 个直接文件组成的薄 HTTP 边界；鉴权、输入与响应投影留在路由，业务
  委托领域模块。
- `images/` 有 26 个直接文件，并包含 `imports/`、`ready-cache/`、`read-models/`；根文件
  承担图片读写、展示、回收站、元数据、缩略图和跨子域图片同步。

### `core/`：平铺的数据库与 Redis 基础设施

`core/` 有 34 个直接文件、46 个源码文件。HTTP 已有自己的 `core/http/` 子目录，但数据库
与 Redis 文件仍以名称前缀平铺：

```text
database-pools.ts              redis-client.ts
database-transactions.ts       redis-business-scripts.ts
database-advisory-locks.ts     redis-business-commands.ts
database-schema.ts             redis-window-limit.ts
database-readiness.ts          redis-json.ts
public-db-admission.ts         redis-pipeline.ts
public-db-fallback.ts          redis-conditional-string.ts
```

- `database-pools.ts` 唯一拥有主查询池和 advisory-lock 池。
- `database-readiness.ts` 在一个 635 行文件中同时保存 contract、relations / columns、权限、
  主键和唯一索引、外键、稳定种子与总编排；检查次序和事务由同一入口维持。
- `redis-client.ts` 是唯一 ioredis client 构造与自定义命令注册点。
- `redis-business-scripts.ts` 保存七个必须原子执行的 Lua 文本；
  `redis-business-commands.ts` 保存 `numberOfKeys`、参数布局、返回解析和类型化调用。
- `public-db-admission.ts` 唯一拥有公开 PostgreSQL fallback 的进程级 FIFO；
  `public-db-fallback.ts` 拥有请求级惰性 reader scope。

### `images/imports/`：53 个平铺文件

5.0.2 的统一导入领域没有职责子目录，53 个源码文件全部直属 `imports/`。它仍只有两套逻辑
队列（upload / import）、一套 Redis canonical 和一套进程级 Worker 资源：

| 5.0.2 文件簇 | 实际职责与唯一所有者 |
| --- | --- |
| `runtime.ts`、`runtime-repository.ts` | 唯一装配 repository、service、token service、Import Worker 与 orphan cleanup Worker。 |
| `session-repository.ts` | 1,243 行 facade；连接命令、严格 reply 解析、错误翻译、订阅与发布。 |
| `session-scripts.ts` | 2,103 行 Lua 生成源；canonical、intent、queue snapshot/action、discovery/read 共十段最终脚本。 |
| `session-*.ts`、`request-hash.ts`、`token-service.ts` | canonical / intent model、身份、key、codec、transition、命令协议与 token。 |
| `queue-*.ts`、`action-scope.ts`、`session-update.ts`、`session-view.ts` | owner queue 快照、SSE、watermark、批量动作、草稿 CAS 和展示投影。 |
| `raw-files.ts`、`raw-upload.ts` | raw 路径、流式接收、generation、lease map、孤儿扫描和目录修剪；所有可变 map 在一个 888 行模块内。 |
| `download-*.ts`、`fetch.ts`、`jsonl.ts`、`weibo*.ts` | 远端来源、安全抓取、JSONL 与微博适配。 |
| `commit-worker.ts`、`commit-intent.ts`、`duplicate-confirmation.ts` | prepared 对象采用、锁、PostgreSQL 提交、重复确认和 completed 回执。 |
| `cancel-session.ts`、`cleanup-queue.ts` | 取消的 resolving / irreversible 边界，以及可重发现资源的尽力重试清理。 |
| `execution-*.ts`、`irreversible-coordinator.ts` | heartbeat、进度、version fencing 与数据库不可取消边界。 |
| `import-worker.ts`、`worker-stage-pools.ts`、`prepare-session.ts`、`session-recovery.ts` | download / prepare / commit 池、Sharp 准备、启动与 Redis 重连恢复。 |
| `orphan-*.ts`、`storage-references.ts` | 60 秒周期、引用快照、保守年龄和停机排空。 |

关键 owner 在 5.0.2 已经明确但物理上聚集在少数长文件：repository listener 只创建一次；
raw 的 `active`、`deleting`、`scanning`、`pruning` map 只有一套；Import Worker、timer、
AbortController 与活动 task 由 runtime 创建并在 shutdown 排空；commit 的 storage lock、
advisory lock、事务和完成发布顺序不可拆开执行。

### `images/ready-cache/`：39 个平铺文件

该目录 39 个文件全部直属根目录，但逻辑上已经有四组：

- `attribute-index*` 与 `filter-index*`：索引构建、存储和读取。
- `derived-*`：derived registry、生命周期、清理、快照与工作策略。
- `counts*` / `filtered-counts.ts`：计数模型、查询与过滤计数。
- `incremental*`、`redis-*`、`fence.ts`：增量同步和 Redis 写入。
- `integrity*`：manifest、抽样和一致性检查。

`coordinator-machine.ts`（637 行）是 phase、pending refresh、active task / abort、mutation
hold 与 rebuild requirement 的唯一状态机；`coordinator.ts` 只装配进程唯一实例。
`query.ts`、`ordered-window.ts`、`keys.ts`、`model.ts`、`revision.ts` 等横切模块留在同一根层。

### `storage/`：37 个平铺文件

37 个文件全部直属 `storage/`，依靠文件名前缀表达职责：

- `backend-*`：配置、注册表、读模型、探测、更新、删除、占用与整后端迁移。
- `driver*`、`local-backend.ts`、`s3-backend.ts`、`s3-request-runtime.ts`：driver 契约、
  工厂、实例生命周期和 local / S3 实现。
- `object-*`、`image-paths.ts`、`storage-namespace.ts`、`public-urls.ts`：对象身份、访问、
  传输、校验、URL 与 namespace。
- `image-storage-migration.ts`、`image-relocation.ts`、`endpoint-rebind.ts`：单图 CAS 搬迁、
  relocation 与端点重绑。
- `move-cleanup-*`：持久 `move.cleanup` 任务的类型、仓储、handler 与 service。
- `maintenance-lock.ts` 是跨以上职责的独占位置锁，因此不是某个前缀簇的私有实现。

注册表配置缓存和 driver 实例缓存相互独立；`image-storage-migration.ts` 是单图锁内重读、
候选写入、校验、PostgreSQL CAS 与不确定提交补偿的唯一原语。

## Web 顶层结构

Web 的依赖方向为：

```text
pages ──► components / hooks / lib
components ──► hooks / lib
hooks ──► lib
```

公开 Home / Gallery 由 `lib/public-route-modules.ts` 动态加载；后台由
`pages/admin/admin-route-modules.ts` 维护唯一角色感知动态模块表。公开入口不可达 uploader，
图片管理员入口不可达用户、存储维护与高级配置等超级管理员页面。

### `pages/admin/`：34 个直属文件

后台共有 82 个源码文件，其中 34 个直接平铺在 `pages/admin/`：账号与登录、后台 shell、
图片管理、检查维护、存储设置、路由模块表等均靠文件名关联。`LogPage.tsx`、`Overview.tsx`、
`SettingsPage.tsx`、`UserAdmin.tsx` 与 `VocabularyAdmin.tsx` 也是独立页面入口。

- `admin-route-modules.ts` 是唯一 lazy import 表；导航预加载复用同一 Promise。
- `AuthenticatedAdminShell` 先完成角色过滤，再加载允许的页面。
- `CheckPage` 只含两种管理员共用的只读检查；`CheckMaintenanceCapability` 才动态承载超级
  管理员维护能力。
- `ImageAdmin.tsx` 是页面装配入口，查询、选择和操作分别由同目录 Hook / model 拥有。

### `pages/admin/uploader/`：33 个直属文件

Uploader 共有 41 个源码文件；除已有的八个 `link-import/` 来源适配文件外，其余 33 个全部
直属根目录：卡片、queue model、API、Upload / Import controller、草稿同步、SSE、raw 上传
和窗口 UI 混排。

| 5.0.2 owner | 生命周期与资源 |
| --- | --- |
| `useUploadQueueOwner` / `useImportQueueOwner` | 两个相互隔离的 `jobsRef`、页码、single-flight 与清空范围。 |
| `useServerImportQueue.ts` | 当前显示队列唯一 SSE、snapshot、connection generation、事件缓冲与 authority recovery。 |
| `useStoredImportDraftSync.ts` | pending / dirty map、250 ms timer、scheduled IDs、batch tail、version 等待与卸载 flush。 |
| `useImportAuthorityHandoffs.ts` | 独立于当前页 DTO 与连接代际的 HTTP handoff fence。 |
| `useImportQueue.ts` | completed pair 去重、水合状态读取和 PostgreSQL 图片查询失效。 |
| `useLocalUploadImport.ts` | Blob URL、XHR、AbortController、文件 intent、raw lane 与 cleanup。 |
| `UploadWorkflowWindow.tsx` | DialogFrame、焦点恢复、滚动边界、mode、详情 / preview 和 cleanup confirmation。 |
| `admin-route-modules.ts` | 后台页面动态加载器；来源弹窗另由 Uploader 内 `lazy()` 按需加载。 |

两套队列 owner 共享 DTO、卡片和窗口外壳，但不共享 SSE、页码、busy、重复确认或动作连接
hold。关闭、重开或切换一边不会读取、取消、清空或阻塞另一边。
