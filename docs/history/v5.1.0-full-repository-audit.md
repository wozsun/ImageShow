## 范围与方法

审计分别从精确基线的独立只读 worktree 和最终 5.1.0 工作树读取 Git 清单。范围只由
`git ls-tree -r --name-only 512c32a...` 与最终 `git ls-files` 决定，不按 diff、行数、
目录密度、文件类型或生成来源抽样。`tests/`、`TODO.md` 与 `AGENTS.md` 按项目约定不受
Git 跟踪，因此不计入下表；它们仍参与本地门禁、计划和开发约束。

对每个清单项执行以下检查：

1. 读取完整字节并计算 SHA-256；检查零字节、重复内容、二进制类型和扩展名分布。
2. 对全部 TypeScript / TSX 建立 AST、静态 import、字面量动态 import、re-export、
   export、入向消费者、短包装函数和长函数清单，并以三个 workspace 的真实 tsconfig
   建立依赖图。
3. 对 CSS 建立 `@import` 图和 selector 清单；对 Web 生产构建读取真实 facade、模块根、
   dynamic importer、CSS owner、原始与压缩体积，不从源码文件名推测分块。
4. 对 JSON / JSONC、SQL、YAML、Shell、Dockerfile、HTML、SVG、Markdown、lockfile 和
   无扩展运行入口逐项核对消费者、生成来源、部署必要性、配置与版本同步、链接和发布边界。
5. 对同名路径比较内容；对仅出现在一侧的路径再比较内容哈希与 Git rename detection。
   逐路径清单把结果区分为未变、同路径修改、纯移动、移动并修改，以及删除 / 拆分 / 合并
   的旧端和新增 / 拆分 / 合并的当前端。语义上的一对多和多对一映射由结构对照文档说明。

逐路径表中的哈希取 12 位前缀便于人工复核。本报告自身不能稳定包含自己的内容哈希，
因此其当前行标为“审计清单自身”；其余最终文件的有序 `路径<TAB>完整 SHA-256` 清单另计算
一个聚合 SHA-256。最终发布候选形成后会重新生成本节数字和逐路径表。

## 发现与处理

### 已删除或内联的无价值包装

| 5.0.2 路径 / 实现 | 5.1.0 处理 | 判断依据 |

| `routes/stored-response-request.ts` | 内联到唯一的公共资源路由消费者 | 只投影请求字段，没有状态、错误翻译或复用协议。 |
| `routes/admin-{tags,themes,authors}.ts` + `admin-entity-routes.ts` | 合并为 `routes/admin-vocabulary.ts` | 三个文件只传入同构配置；一个文件即可保留各自 schema、权限和注册顺序。 |
| `images/imports/session-lock.ts` | 删除，锁 key 由 session keys 的唯一来源生成 | 单消费者转发且制造第二个 key 命名位置。 |

### 直属文件超过 20 个的目录

5.0.2 的 `core`、`images/imports`、`images/ready-cache`、`storage`、Web `pages/admin`、
`pages/admin/uploader` 已形成稳定职责簇并完成归组；`routes` 通过合并无价值的词表 wrapper
从 22 降至 18。最终只有以下两个目录仍超过 20 个直属文件：

- `server/src/images`（26）：根文件横跨图片分类、查询模型入口、展示、正式对象读取、更新、
  回收站和跨子域同步。相同 `image-*` / `trash-*` 前缀不等于相同 owner；强建目录会把单个
  aggregate 的横切入口按词面切开，或制造只有一两个真实成员的层级。稳定的大型子域已经是
  `ingestion/`、`ready-cache/` 和 `read-models/`。
- `web/src/styles/admin`（22）：每个 CSS 入口按真实路由或共享视觉职责由 Vite 追踪 owner。
  `image-*` 等前缀同时服务不同动态能力；再建目录不会形成新的样式所有权，反而增加 import
  路径和误导性的页面绑定。

其余同前缀三文件以上组合也逐组复核。已经位于明确领域目录中的 `queue/action-*`、
`sources/weibo-*`、Web queue `ingestion-*`、gallery `gallery-*` 和样式前缀不再增加一层；
它们的共同职责已由父目录表达，继续嵌套只增加路径深度。`routes/admin-*`、`users/admin-*`、
`images/image-*` 虽有词面前缀，但变化原因和资源 owner 不同，因此不按名称机械归组。

### 状态、副作用与依赖

- Server 单例数量不变：数据库池、Redis client / command 注册、ready-cache coordinator、
  repository listener、Weibo limiter、raw lease registry、worker、清理队列和 storage driver
  registry 各只有一个生产 owner。
- Web 仍只有 Upload / Import 两个隔离 queue owner；每边各自拥有 jobsRef、页码、SSE / snapshot、
  handoff、draft timer、XHR / Blob URL 和清理范围。来源弹窗继续动态加载。
- 依赖图无循环；`core` 不反向依赖业务域，route 不导入 Lua / 私有 worker，ingestion 下层不
  依赖 worker / runtime，公开入口不可达后台 ingestion，图片管理员入口不可达超级管理员页面。
- Redis `imageshow:import:*`、queue 值 `import`、canonical `remote` 和 `import_*` marker 保持
  原样，确保升级时在途会话继续可恢复；公开 HTTP / DTO、配置段、源码、用户文案和 CSS / JS
  父领域名则按批准范围改为 Ingestion → Upload / Import。
- `schema.sql`、占位 `schema-additions.sql` 和数据库结构没有变化；RuntimeConfig 叶子数仍为
  83，执行 `link_image → import` 与旧提交段 `import → ingestion` 的启动归一化和原子写回；
  经明确授权，`import.fill_original_url` 的缺省值改为 `true`，显式 `false` 仍会保留。
