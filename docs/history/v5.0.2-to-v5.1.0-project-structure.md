# ImageShow 5.0.2 → 5.1.0 项目结构对照

本文逐项记录从发布提交
`512c32adb1054bc796101a34bdfb3bf06952f94b` 到 5.1.0 的结构重组。5.0.2 的不可变事实见
[5.0.2 项目结构快照](./v5.0.2-project-structure.md)，现行开发入口见
[项目结构（5.1.0）](../guide/project-structure.md)。

## 版本边界

5.1.0 以内部模块边界、路径和私有职责分配为主，并把同一领域的公开命名一次性收口为
Ingestion → Upload / Import。命名变化包括：

- Server `images/imports/` → `images/ingestion/`，管理路由前缀
  `/api/admin/imports/*` → `/api/admin/ingestion/*`，共享浏览器 DTO 和内部公共类型统一使用
  `Ingestion*`；子来源直接使用 `Upload*` / `Import*`，不保留 `LocalUpload*`、
  `RemoteImport*` 或旧路径转发。
- Web `pages/admin/uploader/` → `pages/admin/ingestion/`，`link-import/` → `import/`；入口、
  工作流、队列、CSS selector 和生产资源名统一使用 ingestion，两个子模式仍为 upload / import。
- RuntimeConfig 远程来源段由 `link_image.*` 改为 `import.*`，共用提交段由旧
  `import.*` 改为 `ingestion.*`。`data/config.json` 在归一化时迁移旧值并原子写回；若新旧名
  同时存在则新名优先。环境变量只读取新的 `IMPORT_*` 与 `INGESTION_*`，不保留旧别名。
- 面向管理员的父领域文案由“上传器 / 导入队列”统一为“内容接入”，子动作仍明确写“上传”
  或“导入”。这只改变术语，不改变交互流程。
- 按用户明确授权，`import.fill_original_url` 的默认值由 `false` 改为 `true`；新配置和缺失该
  字段的旧配置默认把输入 URL 填入“原图 URL”，已显式保存的 `false` 仍原样保留。

以下行为契约保持不变：

- 权限矩阵、输入边界、状态机、请求数量和错误语义；前后端随版本同步切换新 HTTP / DTO 名称。
- RuntimeConfig 的字段集合总量、合法范围、管理设置可见性，以及配置投影、合法性校验、
  归一化和原子写回能力；除上述 `fill_original_url` 默认值外，本版只重命名两个配置段，
  功能性字段增删仍留给 5.2.0。
- `schema.sql`、占位 `schema-additions.sql`、数据库初始化 / readiness 事务顺序。
- Redis 中既有 `imageshow:import:*` key、queue 值 `import`、canonical `remote` 字段、
  `import_*` marker、`numberOfKeys`、Lua KEYS / ARGV / 返回数组与最终脚本文本。TypeScript
  自定义命令标识随源码改为 Ingestion，但持久协议值不改，以便继续处理升级时的在途会话。
- Upload / Import 两个逻辑 owner、canonical、SSE、snapshot、watermark、草稿 CAS、恢复与清理语义。
- 前端 DOM 顺序、ARIA、焦点顺序、视觉、交互、请求数量和 5.0.2 的并发策略；class 与资源
  名称按新术语一一替换，CSS 声明和布局结果保持等价。
- local / S3 driver、对象 key、锁、CAS、持久 `move.cleanup` 和存储维护执行顺序。

5.2.0 计划中的配置删除、进程级资源准入、固定浏览器 lane、watermark / snapshot 优化和草稿
同步调度均未提前实施。

## 目录密度变化

“直属”只统计该目录直接拥有的源码文件，“总计”包含子目录。归组没有使用局部 barrel、旧路径
转发层、tsconfig alias 或模糊 `common` / `helpers` 目录。

| 目录 | 5.0.2 直属 / 总计 | 5.1.0 直属 / 总计 | 结论 |
| --- | ---: | ---: | --- |
| `server/src/core` | 34 / 46 | 20 / 53 | 建立 `database/`、`redis/`；HTTP 结构不变。 |
| `server/src/images/imports` → `server/src/images/ingestion` | 53 / 53 | 5 / 70 | 建立九个职责目录，根层只留装配和公开入口。 |
| `server/src/images/ready-cache` | 39 / 39 | 14 / 39 | 建立 indexes、derived、counts、sync、integrity。 |
| `server/src/storage` | 37 / 37 | 1 / 37 | 建立 backends、drivers、objects、migration、cleanup。 |
| `web/src/pages/admin` | 34 / 82 | 6 / 92 | 建立 shell、account、images、check、storage、advanced-config。 |
| `web/src/pages/admin/uploader` → `web/src/pages/admin/ingestion` | 33 / 41 | 4 / 51 | 建立 queue、workflow、upload、import；父领域不再用 Uploader，远程来源不再局限为 link。 |
| `server/src/images` | 26 / 128 | 26 / 145 | 保留；根文件是图片读写、展示、回收站和跨子域同步，不是单一变化族。 |
| `server/src/routes` | 22 / 22 | 18 / 18 | 收口一个单消费者投影，并合并同构管理词表注册；URL、权限和装配顺序不变。 |

`server/src/images` 仍超过 20 个直属文件，但继续拆分只会把不同变化原因的图片能力硬凑成组；
因此记录为审查后的保留项，而不是遗漏。

## Server 路由映射

5.0.2 的 `stored-response-request.ts` 只有 `public.ts` 一个消费者，仅把 Hono header、HEAD 方法
和取消信号投影为存储响应请求；5.1.0 将其作为 `public.ts` 私有函数，media 与 thumbnail
继续复用同一投影。`admin-tags.ts`、`admin-themes.ts`、`admin-authors.ts` 都只声明一组同构
CRUD 配置并调用 `admin-entity-routes.ts`；5.1.0 将四个文件收口为 `admin-vocabulary.ts`，只
导出一个管理词表注册入口，通用 registrar 留为文件私有实现。tags、themes、authors 仍分别
使用原 schema、query、mutation 和 delete permission，并按原 tags → themes → authors 顺序
注册，因此这些词表 HTTP 路径、中间件、响应与权限没有变化。内容接入路由文件另由
`routes/imports.ts` 改为 `routes/ingestion.ts`，并与共享 DTO 同步切换管理路径前缀。

其余短路由文件仍各自对应独立的 URL、Host、安全或权限边界；例如 ready-cache rebuild
不与深度检查混合，robots 与 CSP report 也不并入普通公共 API。它们不是单消费者转发层。

文件由浏览器上传，URL、JSONL 与微博由 Server 远程导入。内部 mode 因此从 `file` / `link`
同步收口为 `upload` / `import`。父领域用户文案、CSS selector、Vite facade / chunk 与
RuntimeConfig 段名也同步收口；功能字段的增删、默认值和并发语义仍完整留在 5.2.0。
唯一例外是本版明确批准把 `import.fill_original_url` 默认值改为 `true`，它不新增字段或探测。

配置命名映射为：

| 5.0.2 | 5.1.0 | 升级行为 |
| --- | --- | --- |
| `link_image.*` / `LINK_IMAGE_*` | `import.*` / `IMPORT_*` | `data/config.json` 自动迁移；旧环境变量不读取。 |
| 提交段 `import.*` / `IMPORT_COMMIT_*` | `ingestion.*` / `INGESTION_COMMIT_*` | 旧配置段按 commit 字段识别并迁移；新旧并存时新名优先。 |

样式入口由 `styles/admin/upload.css`、`upload-triggers.css` 改为 `ingestion.css`、
`ingestion-triggers.css`；父工作流 selector（如 `.upload-window`、`.import-job`、
`[data-import-*]`）收口为 `.ingestion-window`、`.ingestion-job`、`[data-ingestion-*]`，真正的
Upload / Import 子控件仍保留各自语义。Vite facade / chunk 从 `upload-[hash].js` 与
`upload-[hash].css` 改为 `ingestion-[hash].js` 与 `ingestion-[hash].css`，远程来源弹窗为
`import-source-[hash].js`，共享队列纯能力为 `ingestion-job-utils-[hash].js`；哈希继续由内容决定。

Redis 持久状态仍保留 `imageshow:import:*`、queue 值 `import`、canonical `remote` 和
`import_*` marker。这是升级期间在途会话的协议连续性，不是公开命名兼容层。
